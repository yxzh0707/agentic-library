# Round 1 Day 1 Playbook

> 正式数据到手后的精确执行手册。目标：最快速度完成首次有效提交。

## T+0 min: 数据获取

```bash
# 1. 从 AngelML 平台下载 Round 1 数据
# 预期格式：parquet，路径假设 data/round1_train.parquet + data/round1_test.parquet
mkdir -p data/round1
# 下载到 data/round1/
```

## T+5 min: Schema 验证（必须先做）

```bash
# 2. 立刻跑 schema validator
python -m src.data.schema_validator --parquet data/round1/round1_train.parquet --strict
```

**根据结果分支：**

| 结果 | 行动 | 预计耗时 |
|------|------|---------|
| OK (绿灯) | 直接进入 T+10 | 0 min |
| INFO (小幅差异) | 确认 dense_pad_dim 够用，继续 | 5 min |
| WARNING (显著差异) | 调整 FlatReaderConfig 参数 | 15-30 min |
| CRITICAL (不兼容) | 修 flat_reader.py + model，见下方应急 | 30-60 min |

### CRITICAL 应急清单

- **缺失 meta 列** → 修 `src/data/flat_reader.py` 的 `META_COLUMNS`
- **缺失 domain** → 修 `DOMAIN_NAMES`、`FlatBatch` 字段、`unirec_hybrid.py` 的 `target_aware_pools`
- **新增 domain** → 扩展以上三处 + 更新 head 维度 (7→N+3)
- **特征列数量大幅变化** → 调整 `max_user_int_feats`/`max_item_int_feats`/`dense_pad_dim`

## T+10 min: 数据 EDA + 特征事前分析（暗室校准 Rule 1）

> **暗室校准**：不再"构造完直接扔进模型"。先分析，再决定哪些特征入模。

```python
import pyarrow.parquet as pq
import pandas as pd
import numpy as np

# === 基本统计 ===
table = pq.read_table("data/round1/round1_train.parquet")
df = table.to_pandas()
print(f"行数: {len(df)}")
print(f"列数: {len(df.columns)}")
print(f"正样本率: {(df['label_type'] == 2).mean():.4f}")

# === 序列长度分布（决定 max_seq_len） ===
for domain in ['domain_a', 'domain_b', 'domain_c', 'domain_d']:
    seq_cols = [c for c in df.columns if c.startswith(f"{domain}_seq_")]
    print(f"{domain}: {len(seq_cols)} seq columns")

# === 特征事前分析（暗室校准新增） ===
label = (df['label_type'] == 2).astype(int)

# 过滤到纯标量列（int_feats/dense_feats 中有部分是数组，会让 MI/corr 崩）
def _is_scalar_col(series):
    sample = series.dropna().head(1)
    if len(sample) == 0:
        return False
    v = sample.iloc[0]
    return not hasattr(v, '__len__') or isinstance(v, (str, bytes))

# 各 int 特征与 label 的 mutual info（仅标量列）
from sklearn.feature_selection import mutual_info_classif
int_cols = [c for c in df.columns if 'int_feats' in c and _is_scalar_col(df[c])]
if int_cols:
    X = df[int_cols].fillna(0).astype('int64')
    mi = mutual_info_classif(X, label, discrete_features=True, random_state=0)
    print("Top-10 int features by MI:", sorted(zip(int_cols, mi), key=lambda x: -x[1])[:10])

# 各 dense 特征与 label 的相关性（仅标量列）
dense_cols = [c for c in df.columns if 'dense_feats' in c and _is_scalar_col(df[c])]
if dense_cols:
    corrs = df[dense_cols].astype(float).corrwith(label).abs().sort_values(ascending=False)
    print("Top-10 dense features by corr:", corrs.head(10))

# Dense 维度（决定 dense_pad_dim）
dense_cols = [c for c in df.columns if c.startswith("user_dense_feats_")]
print(f"user_dense_feats: {len(dense_cols)} columns")
```

**关键参数确认：**
- `max_seq_len`: 如果序列列数 > 128，考虑提高到 256 或使用 subsample
- `dense_pad_dim`: 必须 >= 实际 dense 维度，向上取 2 的幂次
- `vocab_size`: 检查 int 特征最大值是否 < 131072

## T+20 min: 范式迁移检查（暗室校准 Rule 2）

> **暗室校准**：在训练前暂停 2 分钟，问一个关键问题。

**必答问题**：这个 CVR 预测任务能否被重定义为另一类已解决的问题？

检查清单：
- [ ] 这是标准的"特征→二分类"吗？还是可以重新定义？
- [ ] 用户行为序列是否可以当作"文本"处理？（2020 冠军的范式迁移）
- [ ] 多 domain 序列是否暗示了图结构或多任务结构？
- [ ] 记录结论到 `decision_log.md`

**如果发现范式迁移机会**：评估改造成本 vs 收益，不要立刻放弃 UniRec-Hybrid，但记录为"备选探索方向"。

## T+25 min: 首次训练（3-seed baseline）

**优先用 CLI 一行命令**（2026-04-23 新增）：

```bash
PYTHONPATH=. python scripts/run_experiment.py \
  --data data/round1/round1_train.parquet \
  --name round1_baseline \
  --model unirec_hybrid \
  --seeds 7,42,123 \
  --epochs 10 --batch-size 64 --lr 1e-3 \
  --tags baseline,unirec_hybrid
```

参数说明：
- `--model unirec_hybrid` 默认 `use_gln=False`（当前最佳 baseline 配置，no-GLN）；要开 GLN 加 `--use-gln`，开 NAL 加 `--use-nal --nal-weight 0.3`
- `--seeds` 触发多 seed 模式，`run_multi_seed` 自动聚合 mean±std 并把每个 seed 单独写 manifest
- `--tags` 让 L2 prior contradiction 检查能匹配（不填则任何 prior 都不触发，`check_knowledge` 返回空）
- 需要改 `max_seq_len` 或 `dense_pad_dim` 时编辑 `scripts/run_experiment.py` 里 `reader_config`，或走下面 Python 路径

**若需要定制 FlatReaderConfig 或更细粒度控制，走 Python 路径**：

```python
from src.training.loop import ExperimentLoop
from src.data.flat_reader import FlatReaderConfig
from src.models.unirec_hybrid import UniRecHybrid

loop = ExperimentLoop(
    project_root=".",
    manifest_path="manifest.json",
    domain_hints_path="docs/domain_hints.md",
)

config = {
    "name": "round1_baseline",
    "data_path": "data/round1/round1_train.parquet",
    "notes": "Round 1 首次 baseline，UniRec-Hybrid 无 GLN",
    "tags": ["baseline", "unirec_hybrid"],
    "reader_config": FlatReaderConfig(
        max_seq_len=128,      # 根据 EDA 调整
        dense_pad_dim=768,    # 根据 EDA 调整
        batch_size=64,        # 数据量大时可提到 256
    ),
    "model_builder": lambda: UniRecHybrid(
        vocab_size=131072,
        hidden_dim=128,
        num_heads=4,
        num_layers=2,
        dense_dim=768,        # 与 dense_pad_dim 一致
        dropout=0.1,
        use_gln=False,
    ),
    "train_config": {
        "epochs": 10,
        "lr": 1e-3,
        "weight_decay": 0.0,
        "grad_clip": 1.0,
    },
}

# 3-seed 验证
summary = loop.run_multi_seed(config, seeds=[7, 42, 123])
print(f"Mean AUC: {summary['mean_auc']:.4f} +/- {summary['std_auc']:.4f}")
```

## T+40 min: QA 检查 + 知识回写

训练完成后 `run_multi_seed` 已自动记录到 manifest。手动检查：

```bash
# 查看 manifest 最新状态
python -c "import json; m=json.load(open('manifest.json')); print(f'Best: {m[\"best_auc\"]:.4f} ({m[\"best_experiment\"]})')"
```

**检查清单：**
- [ ] 3-seed std < 1%？（数据量足够的标志）
- [ ] AUC > 0.65？（sanity check）
- [ ] 没有 NaN / 零 loss？
- [ ] Best epoch > 1？（不是纯 underfitting）
- [ ] 过拟合程度合理？（val_loss/train_loss < 5x）

## T+60 min: 分析 + 迭代规划

首次提交后，对照 leaderboard 结果规划优化方向：

| Leaderboard 排名 | 策略 |
|-----------------|------|
| Top 30% | 做 ablation 验证组件贡献，精细调参 |
| 30-70% | 检查数据管线是否有信息丢失，尝试增大 max_seq_len |
| Bottom 30% | 检查 schema 适配是否正确，可能需要重新审视数据理解 |

### 迭代优先级（按预期收益排序）

1. **max_seq_len 调优** — 从 128 逐步提到 256/512，观察 AUC 变化
2. **学习率 schedule** — 加 cosine decay 或 warmup
3. **batch_size 调优** — 数据量大时 256/512 可能更稳
4. **序列压缩** — subsample vs truncate vs learned compression
5. **组件 ablation** — 用 3-seed 重验 HeadMixing/TargetAware/PerTokenFFN
6. **NAL 重试** — 正式数据量大了，NAL 可能变有效
7. **Self-Attention 重试** — 同理

## 提交节奏

- **每日 3 次上限**，不要浪费
- 建议：上午 1 次（当前最佳）、下午 1 次（最新实验）、晚上 1 次（留给紧急修复）
- Leaderboard 19:00 AOE 更新

## 紧急回滚

如果正式数据跑出 AUC < 0.5：
1. 检查 label 提取逻辑（label_type==2 是否还对）
2. 检查数据是否被 shuffle 了但有时序依赖
3. 用 `--skip-schema-check` 跳过 schema 验证单独测 reader
4. 回退到 vendor 框架验证数据是否能正常加载
