# 数据画像 v2 — 17 次实验后的实证总结

**日期**: 2026-05-06
**触发**: I-635 / I-638 / I-639 三连 KILL，重新审视为什么 17 次实验只有 2 个真正涨分。
**目的**: 为今后**每个新实验**提供"该不该做"的判断依据。新实验起手必须 review 此文档。

---

## 第 1 部分：数据画像（实证事实）

| 性质 | 实验依据 | 推论 |
|---|---|---|
| **train/test item_id 几乎无交集** | I-608 -0.0003 + I-635 -0.0070 双独立验证 | 任何"绑 train item_id"的特征**必死** |
| **train/test uid 几乎无交集** | I-503 关 cold restart -0.014（一旦不重置，user_id memorization 把 LB 拉爆） | user_id memorization 是陷阱，不是特征 |
| **5 天训练窗 CTR 4× 漂移**（D0=2.84% → D9=11.74%） | baseline 数据统计 | 时间漂移真实，但单纯加更多时间维度不行（I-625 已饱和） |
| **5% 正样本率（label_type==2）** | 数据统计 | BCE 近最优，重赋权全死（focal × 2 + pairwise × 2 = 4/4 KILL） |
| **label_type 三档（0/1/2）** | EDA | 我们一直只用 ==2 当 binary 标签，**==0/==1 完全没作监督**（关键金矿） |
| **val ≠ LB 9/10 次** | I-601/I-624/I-615/I-616/I-619/I-630/I-631/I-635/I-638/I-639 | val<0.001 是**噪声不是信号**，唯一信任 LB |
| **架构 saturated at d_model=64** | I-604 layer 2→3 -0.006 | capacity 不是瓶颈 |
| **demo_1000 缺 label_type==0 行** | I-635 schema audit 发现 | demo_1000 EDA 不可信外推到全量；schema audit 必须在 Taiji 上做 |
| **vendor reinit_threshold=0 = 全部 reset** | model.py:1498 实证 | "高基数选择性重置"是误解，实际每轮重置所有非-time embedding |
| **PyTorch 2.6+ SDPA 全 mask 已修复** | 本地复现验证 | Xiaohongshu 帖子 NaN bug 不影响我们 |

## 第 2 部分：17 次实验的统一失败/成功二分法

### ✅ 真正涨分的（PROMOTE 或 marginal +EV）

| 实验 | 引入了什么 | 共有性质 |
|---|---|---|
| I-605 seq-time Fourier+recency | 用户序列内部时间编码 | **不依赖具体身份，是 user-internal 时间模式** |
| I-625 gap features | 用户序列连续事件时间差 Fourier | 同上 |
| I-617 dow onehot (+0.0006 marginal) | 7 维 sparse 时间编码 | 同上 |
| I-606 amp+compile | 工程加速 | 不算 +EV 但+速度 |

### 🔴 失败的（13 个，按失败模式分组）

#### Pattern A — 依赖 train-time 身份（4/4 死）
| 实验 | LB Δ | 失败根因 |
|---|---|---|
| I-608 item_id_hash 1M sparse | -0.0003 | 测试 item_id 全新 → embedding 没学过 |
| I-635 item heat 多窗口 | -0.0070 | 测试 item_id miss artifact → 特征坍缩为 global 常数 |
| I-624 target-aware token gate | -0.0022 | gate 由 target item 驱动 → 受新 item 影响 |
| I-639 time-feat context gating | -0.0025 | gate context 含 target item embedding → 同 I-624 |

#### Pattern B — 纯重赋权 / 正则化，无新信号（5/5 死）
| 实验 | LB Δ | 备注 |
|---|---|---|
| I-630 focal α=0.25 | -0.0058 | 重赋权 |
| I-631 focal α=0.10 | -0.0089 | 重赋权 |
| I-632 PWiseR | -0.0044 | pairwise 重组合现有信号 |
| I-632b Combined-Pair | -0.0062 | 同上 |
| I-638 item_id mask | -0.0122 | 移除信号≠加信号 |

#### Pattern C — 冗余信号，I-625 已吸收（4/4 死）
| 实验 | LB Δ | 备注 |
|---|---|---|
| I-615 freq sweep | -0.0047 | 时间频率冗余 |
| I-616 hour onehot | -0.0049 | 时间维度冗余 |
| I-619 freq decoupled | -0.0031 | 同上 |
| I-604 layer 2→3 | -0.0058 | 容量冗余 |

## 第 3 部分：元规则（forward-looking）

### 🚫 默认 KILL 规则（已实证，不再投实验 quota 验证）

1. **凡是依赖 train item_id 或 user_id 身份的特征/机制 → default KILL**
   - 不再做：item_id embedding 变种、item-conditioned gating、user_id-conditioned gating
2. **凡是纯重赋权 / 正则化 / 重组合现有信号的 loss → default KILL**
   - 不再做：focal/BPR/RankNet/Combined-Pair 任何变体、pure dropout 变体、layer-wise 重赋权
3. **凡是给 I-625 时间维度加更多频率 / 桶 / 编码的 → default KILL**
   - 不再做：abs-time freq sweep、hour/dow 单点上 stack、recency 桶细化

### ✅ 真正可能涨分的实验必须满足"双条件"

**条件 1：引入新信号**（不是重组现有）
- ✅ 新维度信息（label_type==0 没用过 / cate-level 统计没用过 / semantic ID 没用过）
- ❌ 现有维度的非线性变换、reweight、多任务无新信号

**条件 2：OOV-safe**（train/test 共享）
- ✅ user-internal 序列模式、cate 级共享特征、attribute-derived semantic code
- ❌ train item_id binding、train item embedding lookup、specific-id memorization

### 元规则 cheat-sheet（贴在 active_state 顶）

| 候选机制 | 引入新信号？ | OOV-safe？ | 默认判断 |
|---|---|---|---|
| 任何 reweight / pairwise / focal 变体 | ❌ | ✅ | **KILL** |
| 任何 item_id-bound 特征 | ✅ | ❌ | **KILL** |
| 时间频率 / 桶 / 编码加更多 | ❌ | ✅ | **KILL**（I-625 已饱和） |
| **Cate-level OOF Bayesian** | ✅ | ✅（前提：cate 是 train/test 共享） | **候选** |
| **Funnel 三档监督（label_type 0/1/2）** | ✅ | ✅ | **候选** |
| **Semantic IDs from attributes** | ✅ | ✅ | **候选** |
| **User-internal 新时间结构**（如 user-internal 速率变化） | ✅ | ✅ | **候选**（但要避免与 I-625 冗余） |

## 第 5 部分：实验启动 checklist

每次新实验起手前 review：
1. ☐ 该实验引入的新信号是什么？（一句话）
2. ☐ 这个信号在 train/test 都存在吗？（OOV-safe？）
3. ☐ 已经做过的 17 个实验里有同机制变种吗？
4. ☐ 它属于元规则的"默认 KILL"族吗？
5. ☐ 实施成本（小时）？预期 LB Δ 量级？

任何一条不通过 → 不投 GPU quota。
