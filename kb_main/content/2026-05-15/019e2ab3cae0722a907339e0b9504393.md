## 综述

### 0. CVR Survey — 转化率预测综述

**论文：** Conversion Rate Prediction in Online Advertising: Modeling Techniques, Performance Evaluation and Future Directions
**链接：** https://arxiv.org/abs/2512.01171 | **来源：** Information Processing & Management, 2026 | 99 页综述

#### 解决的问题

对在线广告 CVR 预测进行全面系统的文献综述，将现有模型按底层技术分为六大类，梳理方法论演进脉络，填补该领域缺乏系统性分类与比较的空白。

#### 核心创新点

- **六大类模型分类体系**：涵盖传统 ML、深度特征交互、序列建模、多任务学习（ESMM/MMoE）、去偏方法、语义增强方法
- **四大前沿方向识别**：语义增强（semantics-enriched）、归因增强（attribution-enhanced）、去偏 CVR 预测（debiased）、CTR 与 CVR 联合建模

#### 不足与局限

- 综述性质，不含新模型或实验验证
- 未涵盖 2026 年最新的统一 Transformer 架构（HyFormer、MixFormer 等）

#### 对赛题的启发

- **CVR 标签稀疏性不可忽视**：转化样本极少，需要从有限正样本中高效学习。可考虑多任务学习（同时预测 CTR+CVR）来缓解
- **去偏技术值得尝试**：若数据存在选择偏差，考虑 IPS（逆倾向加权）、doubly robust 等方法
- **别只盯架构**：标签稀疏、归因、校准同样会卡分

## 第一梯队：最值得优先读的 6 篇

### 1. HyFormer

**论文：** HyFormer: Revisiting the Roles of Sequence Modeling and Feature Interaction in CTR Prediction
**链接：** https://arxiv.org/abs/2601.12681 | **来源：** 字节跳动/抖音 | 已部署于抖音搜索

#### 解决的问题

大规模推荐系统需要同时处理超长用户行为序列和多样化的非序列特征，但传统"序列编码器 + 特征交互模块"两阶段流水线导致信息流割裂、参数分配不均衡。

#### 核心创新点

- **Query Decoding**：将非序列特征编码为 Global Tokens，通过 cross-attention 从长行为序列中解码信息。K/V 来自序列编码器的逐层输出，Q 由非序列特征和序列池化摘要经 MLP 投射生成
- **Query Boosting**：采用 MLP-Mixer 风格的 token mixing（非 self-attention），将解码后的序列感知 Query 与非序列 tokens 拼接后跨 token 信息聚合
- **多序列独立处理**：不同行为序列（点击、购买等）独立 Query tokens 解码，通过 Query Boosting 实现跨序列交互
- **灵活的序列编码器**：支持 Full Transformer / LONGER 式高效编码 / 轻量 SwiGLU 三种变体

#### 不足与局限

- 缺少推理延迟的量化报告，仅报告训练 FLOPs
- MLP-Mixer 在 token 数量较多时是否仍优于 attention 未充分验证
- 仅在搜索场景验证，场景迁移性待验证
- 对比 OneTrans 变体优势约 0.06-0.09% AUC，差距不大

#### 对赛题的启发

- **Query Decoding 是异构 token 融合的优秀范式**：将非序列特征转化为 Query，通过 cross-attention 从序列中提取信息，直接适用于赛题
- **MLP-Mixer 替代 self-attention 可降低延迟**：参数更少，比 full self-attention 更高效
- **多序列独立编码 + 统一交互**：各序列独立编码但在 Query Boosting 阶段统一交互，避免简单 merge 导致的性能退化（merge 损失 0.06% AUC）
- **Global Token 天然支持可堆叠设计**：每个 block 输出的 Global Tokens 直接传入下一个 block
- **核心理念：不要把所有特征暴力拼成一大串 token，而是用少量 global tokens 去读长序列**

### 2. MixFormer

**论文：** MixFormer: Co-Scaling Up Dense and Sequence in Industrial Recommenders
**链接：** https://arxiv.org/abs/2602.14110 | **来源：** 字节跳动/抖音 | 已部署于抖音和抖音极速版

#### 解决的问题

现有 Transformer 推荐模型将序列建模和特征交互作为独立模块，使用独立参数化，导致参数分配不均和缩放效率低下。MixFormer 通过共享参数空间实现序列和稠密特征的联合缩放（co-scaling）。

#### 核心创新点

- **无参数 HeadMixing**：将非序列特征投射为 N 个 head 后，通过 reshape-transpose-flatten 实现跨 head 信息交换，完全不引入可学习参数
- **三阶段统一 Block**：
  1. Query Mixer：HeadMixing 实现非序列特征间交互
  2. Cross Attention：每个 head 独立对行为序列做 attention
  3. Output Fusion：per-head SwiGLU FFN 独立精炼输出
- **User-Item Decoupling（UI-MixFormer）**：mask 矩阵分离 user/item 侧，user 侧计算跨候选共享，FLOPs 降低约 36%
- **轻量高效**：仅 4 层 block、16 heads 即达 SOTA，FLOPs 仅 3,503 GFLOPs（对比 OneTrans 23,371 GFLOPs）

#### 不足与局限

- HeadMixing 无参数，本质上只是固定置换变换，表达能力可能不足
- 仅 4 层固定深度，未做层数消融
- Head 间信息交换仅通过 HeadMixing 一步完成，缺少更深层跨 head 交互
- 未在电商 CVR 场景验证

#### 对赛题的启发

- **HeadMixing 是满足延迟约束的利器**：零额外参数和计算开销，但有效实现非序列特征间信息交换
- **User-Item Decoupling + KV Cache 共享**：user 侧计算跨候选共享，减少约 36% 计算量
- **三阶段 block 天然支持堆叠**：功能明确——特征交互、序列聚合、输出精炼
- **Per-head FFN 优于 shared FFN**：不同 field 含义不同，独立 FFN 更合适
- **如果想做一个更工程化、可部署感更强的统一模型，MixFormer 很值得重点看**

### 3. OneTrans

**论文：** OneTrans: Unified Feature Interaction and Sequence Modeling with One Transformer in Industrial Recommender
**链接：** https://arxiv.org/abs/2510.26104 | **来源：** WWW 2026 accepted | 已部署于电商场景

#### 解决的问题

推荐系统中特征交互和序列建模长期独立发展、参数化分离，导致信息流受限、无法在每一层都进行深度交互。OneTrans 用一个统一 Transformer 同时实现两者。

#### 核心创新点

- **统一 Tokenizer**：
  - S-tokens（序列）：多种行为序列通过 sequence-specific MLP，支持时间戳感知交叉排列（效果更好）或按行为拼接
  - NS-tokens（非序列）：支持 Group-wise（语义分组各组独立 MLP）和 Auto-Split（全部特征单 MLP 投射再切分，效率更高）
- **混合参数化**：S-tokens 共享 Q/K/V 和 FFN 权重（同质性强）；NS-tokens 使用 token-specific 独立参数（异构性强）。独立参数比共享高 0.29% UAUC
- **因果注意力 + 两阶段 KV 缓存**：
  - Stage I（每请求一次）：处理所有 S-tokens，缓存 K/V
  - Stage II（每候选一次）：仅计算 NS-tokens 并 cross-attend 到缓存
  - 跨请求缓存：复用上次 S-tokens 缓存，仅计算增量 ΔL
- **金字塔堆叠**：逐层递减 S-token Query 数量（如 1190→12），计算量降约 3 倍，性能损失仅 0.42% CVR UAUC
- **可学习 [SEP] token**：不同行为序列间插入分隔符，移除后 UAUC 下降 0.32%

#### 不足与局限

- 全注意力 O(L²) 复杂度，FLOPs（23,371 GFLOPs）远高于 MixFormer（3,503 GFLOPs）
- 因果注意力限制了 NS-tokens 对 S-tokens 的影响方向（S-tokens 不能 attend 到 NS-tokens）
- 延迟优化高度依赖工程手段（FlashAttention、混合精度、KV 缓存）

#### 对赛题的启发

- **最贴题的 Tokenizer 设计**：直接将所有特征统一 tokenize 为一个序列，是赛题要求的最直接解法
- **混合参数化经过消融验证有效（+0.29%）**：S-tokens 共享参数、NS-tokens 独立参数，可直接采用
- **金字塔堆叠是满足延迟约束的关键手段**：逐层减少序列 token Query 数量
- **时间戳感知交叉排列优于简单拼接**：若赛题数据含时间戳，优先使用 interleaving
- **[SEP] token 零成本提升（+0.32%）**
- **线上 GMV 提升 5.68%**：在电商 CVR 场景已验证，是最有说服力的参考
- **最适合抄输入设计和 serving 思路，搭第一个 baseline 优先读它的 tokenizer**

### 4. LONGER

**论文：** LONGER: Scaling Up Long Sequence Modeling in Industrial Recommenders
**链接：** https://arxiv.org/abs/2505.04421 | **来源：** 字节跳动, RecSys 2025

#### 解决的问题

工业推荐系统处理超长用户行为序列（最长 5000 个 token）的效率与效果平衡问题。传统方法要么截断序列丢失长期兴趣信号，要么用独立检索阶段引入信息瓶颈。

#### 核心创新点

- **Global Token 机制**：引入目标 item 表示、CLS token、用户 ID embedding 等作为全局锚点，拥有对整个序列的完整注意力感受野
- **Token Merge + InnerTransformer**：相邻 token 以压缩比 K 分组合并（K=8 时 FLOPs 减少约 43%），InnerTransformer 捕获组内交互避免信息损失
- **混合注意力策略**：第一层 Cross Causal Attention（Query 来自全局 token + 采样序列 token），后续层 Self Causal Attention，仅采样 40% 序列即可保留 95% 以上性能
- **工程三板斧**：混精度训练（+18% 吞吐）、激活重计算、KV Cache 推理（吞吐量下降从 -40% 降至 -6.8%）
- **幂律缩放**：参数量与 AUC（R²=0.987）、FLOPs 与 AUC（R²=0.967）均呈强幂律关系

#### 不足与局限

- 仅关注序列特征建模，对非序列特征交叉建模未深入探索
- Token Merge 的压缩比 K 是效率与精度的硬性 trade-off
- Query 选择策略较朴素（"最近 100 个 item"优于可学习 Query）

#### 对赛题的启发

- **Global Token 是统一多类型 token 的关键桥梁**：将非序列特征编码为全局 token，与序列行为 token 在注意力层中交互
- **Token Merge + InnerTransformer 直接控制推理延迟**：可控压缩比减少序列长度
- **40% 采样保留 95% 效果**：显著降低推理计算量
- **时间差编码**：`log(timestamp[i] - timestamp[i-1] + 1.0)` 简单有效，可直接复用
- **凡是历史行为很长、时延又紧的方案，都应该先过一遍 LONGER**

### 5. DHEN

**论文：** On the Practice of Deep Hierarchical Ensemble Network for Ad Conversion Rate Prediction
**链接：** https://arxiv.org/abs/2504.08169 | **来源：** Pinterest, WWW 2025

#### 解决的问题

CVR 预测中单一特征交叉模块（纯 MLP 或纯 Transformer）表达能力不足。通过层次化堆叠多种异构特征交叉模块实现显著 AUC 提升。

#### 核心创新点

- **层次化异构模块堆叠**：最优配置为 2 层——第 1 层 MLP + Transformer，第 2 层 MLP + MaskNet，sum 融合。2 层 DHEN 比最优单层 Transformer 提升 0.31% AUC
- **统一 3D 张量输入**：所有特征统一投影到 ℝ^(B×L×D)（D=64），确保与任意特征交叉模块兼容——实现"可堆叠"的关键
- **五类行为序列独立建模**：搜索 / 自然内容 / 广告互动 / 匹配转化 / 归因转化五类序列保持独立性
- **NAL 自监督辅助损失**：InfoNCE 对比学习预测未来行为（Next Action Loss），比 MLM 高 0.5% AUC。发现"预测未来和最近行为比预测过去行为更有帮助"
- **多任务学习**：共享 backbone 同时预测多个 CVR + CTR 辅助任务（CTR 头仅训练不上线），大幅增加训练标签量

#### 不足与局限

- 3 层 DHEN 出现过拟合，堆叠深度有天花板
- 模块组合搜索空间巨大，最优配置依赖大量实验枚举
- 推理成本较高（340M 参数，年增基础设施成本 120 万美元）
- 在线实验 CTR 下降 2.70%，虽然转化量提升

#### 对赛题的启发

- **统一 3D 张量投影是"可堆叠模块"的核心设计模式**：将所有特征投影到 ℝ^(B×L×D) 后任意模块都可堆叠，应直接采用
- **异构模块组合优于同构堆叠**：block 设计应支持不同类型的特征交叉操作
- **NAL 自监督损失直接用于解决 CVR 标签稀疏**：InfoNCE-based Next Action Loss 验证获 2.18% AUC 提升，实现简单
- **CTR 辅助多任务头**：共享 backbone + CTR 训练头可大幅增加有效训练样本
- **2 层是 CVR 场景的甜蜜点**：超过需强正则化
- **CVR 题里，loss 和 label sparsity 处理经常跟架构同等重要**

### 6. RankMixer

**论文：** RankMixer: Scaling Up Ranking Models in Industrial Recommenders
**链接：** https://arxiv.org/abs/2507.15551 | **来源：** 字节跳动, 2025

#### 解决的问题

工业推荐排序模型在 GPU 上算力利用率极低（MFU 仅 4.5%），导致模型规模无法有效扩展。RankMixer 将 MFU 提升至 45%，在延迟基本不变的情况下将参数量扩展 100 倍至 10 亿规模。

#### 核心创新点

- **Multi-head Token Mixing 替代 Self-Attention**：将 embedding 切分为 H 个 head，跨 token 重排对应 head——无参数操作，避免 O(T²) 计算
- **Per-token FFN（独立 FFN）**：每个 feature token 拥有独立 FFN 权重，保持子空间隔离性。共享 FFN 损失 -0.31% AUC
- **Sparse MoE + ReLU 路由 + DTSI 训练**：1/8 稀疏率保持近满精度，100 倍参数增长仅 3 倍延迟增加
- **硬件感知设计**：Per-token FFN 创造大 GEMM 运算，MFU 从 4.5% 提升至 45%（10 倍）
- **缩放方向等价性**：宽度 D、深度 L、token 数 T 在相同参数量下产生几乎相同性能

#### 不足与局限

- 序列特征通过独立"Sequence Module"处理后才进入 tokenization，序列建模部分较薄弱
- Token Mixing 交互模式固定（仅 head 维度重排），self-attention 仅低 0.03% AUC 但灵活性更高
- 高活跃用户收益递减（+0.124% vs 低活跃 +0.457%）

#### 对赛题的启发

- **Per-token FFN 是处理异构多域特征的最优范式**：不同 feature token 需要独立 FFN 参数，应直接采用
- **Token Mixing + Per-token FFN 作为核心 building block**：结构简洁、可堆叠、推理高效
- **硬件感知设计是满足延迟约束的根本**：优先使用大 GEMM 运算而非多个小操作
- **Sparse MoE 是延迟约束下扩展参数量的利器**
- **混精度推理**：FP16 矩阵运算 + FP32 归一化，可获 45% 吞吐量提升和 31.5% 延迟降低
- **feature interaction block 不一定要用标准 attention，硬件友好的 mixing block 可能更适合比赛延迟约束**

### 7. Yahoo CVR Self-supervised Pre-training

**论文：** Improving Conversion Rate Prediction via Self-Supervised Pre-Training in Online Advertising
**链接：** https://arxiv.org/abs/2401.16432 | **来源：** Yahoo, IEEE BigData 2023

#### 解决的问题

在线广告 CVR 中"点击稀少、归因转化更稀少"的数据稀疏问题。直接将非点击归因的转化数据加入训练会破坏模型校准（calibration），论文通过自监督预训练在不损害校准的前提下利用更多数据。

#### 核心创新点

- **Auto-encoder 自监督预训练**：Encoder 将类别特征压缩为 12 维 code（tanh 有界），Decoder 对每个类别列做多分类重建。模型仅约 10⁵ 参数，极其轻量
- **校准保护机制**：Auto-encoder 在全量转化数据上训练（含非点击归因），CVR 模型仅在点击归因转化上训练。code 作为额外特征输入，信息传递但不污染标签分布
- **RFF 非线性化**：Random Fourier Features 将 12 维 code 映射到 200 维，近似高斯 RBF 核，提升 15% logloss 和 3.6% AUC
- **延迟零增加**：code 对每个类别只需计算一次并缓存，推理时直接查表

#### 不足与局限

- 仅使用高层级类别特征，信息粒度受限
- 基础 CVR 模型较简单（因子分解机 + 逻辑回归）
- 预训练 12 维 code 信息压缩率极高
- Auto-encoder 重建目标与 CVR 目标不对齐

#### 对赛题的启发

- **核心思路可升级**：对全量曝光/点击数据做自监督预训练（masked feature prediction），提取的 representation 作为额外 token 输入统一模型
- **校准保护的架构分离原则**：辅助数据仅通过特征传递（而非标签混合）影响主模型
- **预计算 + 缓存 + 查表策略**：将复杂计算的特征离线预计算，推理时查表拼接，满足延迟约束
- **先把"更广的转化信息"拿来做预训练表征，再回到主 CVR 任务**

### 8. HHFT

**论文：** HHFT: Hierarchical Heterogeneous Feature Transformer for Recommendation Systems
**链接：** https://arxiv.org/abs/2511.20235 | **来源：** 阿里巴巴/淘宝 | 已在生产环境部署

#### 解决的问题

传统 Transformer 对所有异构特征使用统一的 QKV 投影，导致不同语义空间的特征在注意力计算中产生语义混淆（semantic confusion），限制特征交互的有效性和可扩展性。

#### 核心创新点

- **语义特征分块**：将特征按语义分为 User / Item / Query / Sequence 四个 block
- **异构 Transformer 编码器**：每个 block 拥有独立的 Q/K/V 投影和 FFN，先 block 内语义对齐，再拼接做 cross-block attention
- **Hiformer 层**：全局复合投影（composite projection），拼接所有 block 表示通过全局权重矩阵联合投影，捕获超越 pairwise 的高阶跨 block 交互
- **宽度优先扩展**：扩展 token 维度（宽度）比增加层数（深度）带来更大 AUC 增益

#### 不足与局限

- 序列特征处理不够明确，缺少对时序性的专门建模（如 causal masking）
- 仅 1 层 Heterogeneous Transformer + 1 层 Hiformer，堆叠深度极浅
- 推理延迟未报告
- Block 划分方式手工设计，依赖领域知识

#### 对赛题的启发

- **Block-specific QKV + cross-block attention 是异构特征统一建模的优秀范式**：直接借鉴"分块独立投影 → 拼接 → 统一注意力"
- **Block-specific FFN 防止语义混淆**：non-sequential 和 sequential 各用独立 FFN
- **宽度优先扩展策略**：在延迟约束下，优先增大 hidden dim 而非层数
- **如果统一 tokenizer 太"糊"，这篇给了折中方案：先语义分块，再统一交互**

### 9. MTGR

**论文：** MTGR: Industrial-Scale Generative Recommendation Framework in Meituan
**链接：** https://arxiv.org/abs/2505.18654 | **来源：** 美团 | 已在主流量部署

#### 解决的问题

先前的生成式推荐模型为兼容 Transformer 架构不得不放弃 DLRM 中的交叉特征（cross features），但实验证明这导致显著性能退化，且无法通过扩大规模弥补。

#### 核心创新点

- **Cross Feature 保留策略**：将交叉特征作为候选 item token 的一部分嵌入。移除 cross feature 使增益完全消失（CTR GAUC 下降 1.35%，CTCVR 下降 2.01%）——最关键的组件
- **Group-Layer Normalization（GLN）**：按特征域（user/sequence/candidate）分组做 LayerNorm，确保不同语义空间在进入 attention 前分布对齐
- **动态 Masking 三规则**：
  - 静态序列（画像 + 历史行为）→ 对所有 token 可见
  - 实时行为序列 → 因果 masking
  - 候选 item token → 仅对自身可见（防候选间信息泄漏）
- **User-level 压缩**：用户特征和历史序列只计算一次，多个候选共享，实现次线性推理成本
- **Scaling 表现**：展示了 power-law scaling 关系，small→large 持续提升

#### 不足与局限

- 推理 FLOPs 仍然很高（DLRM 的 65 倍）
- 对 cross feature 的强依赖需要工程经验
- 训练框架复杂度高（TorchRec、动态哈希表、All-to-all 通信等）

#### 对赛题的启发

- **交叉特征必须保留**：这是 MTGR 最强信号——统一架构中不能丢弃 cross features
- **GLN 是低成本高收益组件**：异构特征统一 token 化后按域分组归一化，几乎不增加延迟。**强烈建议采用**
- **动态 Masking 三规则可直接复用**：序列 token → causal mask，非序列 token → full-visible mask，候选 token → 隔离 mask。恰好解决"统一架构处理两类 token"的注意力可见性问题
- **User-level 压缩 / KV Cache**：缓存用户侧表示，仅重新计算候选部分
- **就算做统一 backbone，也别轻易丢掉手工或统计 cross features**

### 10. Climber

**论文：** Climber: Toward Efficient Scaling Laws for Large Recommendation Models
**链接：** https://arxiv.org/abs/2502.09888 | **来源：** 网易云音乐 | 日活千万级部署，年度最高线上增益（+12.19%）

#### 解决的问题

Transformer 在推荐系统中 scaling 效果不理想——由于多源数据异构性和毫秒级延迟约束，简单增大模型不能稳定带来收益。Climber 探索了推荐系统中 Transformer 的高效 scaling law。

#### 核心创新点

- **多尺度序列提取（MSE）**：将完整行为序列按业务策略（点击/收藏/分享）分解为 K 个子序列，复杂度从 O(n_s²d) 降为 O(Σn_k²d)
- **自适应 Transformer 层（ATL）**：动态温度调制，softmax 温度系数受提取策略和推荐场景影响，替代固定的 √d_k
- **Bit-wise Gating Fusion（BGF）**：K 个子序列 block 输出通过 sigmoid 门控融合，比简单拼接更精细
- **单用户多物品批处理 + KV Cache**：推理速度比 DLRM 快 2.92-14.38 倍
- **Scaling Law 发现**：FLOPs > 10^8.2 时 Transformer 才优于 DLRM；平衡扩展策略（交替增加序列长度和层数）优于单因素扩展

#### 不足与局限

- 对 non-sequential 特征处理不明确，未显式说明静态特征如何处理
- MSE 子序列划分依赖业务策略和领域知识
- 主要在序列推荐场景验证

#### 对赛题的启发

- **多尺度序列提取直接用于降低 attention 复杂度**：将长行为序列拆分为多个短子序列独立 attention 再融合，满足延迟约束的关键技术
- **动态温度调制成本极低但有效**：每个 block/层学一个温度标量即可
- **KV Cache 是推理加速核心手段**
- **Scaling Law 指导模型配置**：确保 FLOPs 超过交叉点（10^8.2），采用平衡扩展策略
- **BGF 门控融合**：多 block 输出融合时用 bit-wise sigmoid gating 而非简单 concat

## 第三梯队：创新/扩展法则

### 11. TokenMixer-Large

**论文：** TokenMixer-Large: Scaling Up Large Ranking Models in Industrial Recommenders
**链接：** https://arxiv.org/abs/2602.06563 | **来源：** 字节跳动, 2026

#### 解决的问题

RankMixer 的升级版。在深层堆叠时遭遇残差路径不畅、梯度消失、MoE 稀疏化不完整等瓶颈，无法稳定扩展到数十亿参数。

#### 核心创新点

- **Mixing-and-Reverting**：将 token mixing 拆成对称两阶段——混合成 H 个组，再还原回 T 个 token，确保输入输出维度一致，实现稳定残差传播和深层堆叠
- **语义分组 Tokenization**：按语义分组（user/item/seq/cross），各组独立 MLP 映射 + 全局聚合 token
- **Inter-layer Residuals + Auxiliary Loss**：每 2-3 层跨层残差连接 + 低层辅助 loss
- **Sparse Per-token MoE**：1:2 稀疏率近乎零性能损失
- **FP8 量化**：1.7x 推理加速
- **成功扩展到 15B/7B**：在电商（GMV +2.98%）、广告（ADSS +2.0%）、直播（收入 +1.4%）三大场景落地

#### 不足与局限

- 序列建模仍依赖外部模块（DIN/LONGER），非真正端到端统一
- MoE 超过 1:2 稀疏时负载均衡恶化
- 深度依赖大量训练数据（500M-2B 参数需 60 天数据）
- 工业专属优化（kernel fusion、Token Parallel）难复现

#### 对赛题的启发

- **语义分组 Tokenization 与赛题数据高度吻合**：User Features / Ads Features / Context Features / Cross Features 四类非序列特征各自独立 MLP 映射
- **Mixing-and-Reverting 作为轻量统一 block 候选**：线性复杂度，非常适合延迟约束
- **残差设计对深层堆叠至关重要**：inter-layer residual 和 pre-norm（RMSNorm）是必须的
- **MoE 是性价比高的参数扩展手段**
- **如果想做 scaling 实验，梯度路径、残差设计和 MoE 稀疏化是先要想清楚的**

### 12. Wukong

**论文：** Wukong: Towards a Scaling Law for Large-Scale Recommendation
**链接：** https://arxiv.org/abs/2403.02545 | **来源：** Meta, 2024

#### 解决的问题

推荐模型不像 LLM 那样展现清晰的 scaling law，核心原因是现有架构（DCNv2、DLRM 等）扩展机制效率低下，增大复杂度后性能迅速饱和。

#### 核心创新点

- **纯堆叠分解机架构**：每层包含 FMB（Factorization Machine Block，显式两两交互）+ LCB（Linear Compression Block，线性重组），通过残差连接和 LayerNorm 输出
- **指数级交互阶数增长**：数学归纳证明 l 层堆叠后可捕获 1 到 2^l 阶交互——Wukong 能持续 scaling 的理论基础
- **低秩 FM 优化**：可学习投影矩阵将 O(n²d) 降到 O(nkd)
- **协同扩展策略**：先增层数 l → 再增 MLP 尺寸 → 再增 k 和 n_F
- **实证 Scaling Law**：跨两个数量级（到 100+ GFLOP/example）持续提升

#### 不足与局限

- **完全缺乏序列建模能力**：没有任何机制处理用户行为序列的时序依赖
- 交互模式单一（二阶堆叠）
- 公开数据集改进幅度在小数点后第三位
- 无 MoE 等稀疏机制，scaling 靠增加 dense FLOPs

#### 对赛题的启发

- **FMB 作为 non-sequential 特征交互 block 的候选**：赛题的非序列特征本质就是 multi-field 交互问题
- **Scaling Law Innovation Award 的方向参考**：方法论（固定架构 → 多维度协同扩展 → 测量幂律关系）可直接用于 scaling 实验设计
- **低秩 FM 在延迟约束下更高效**：O(nk) 替代 O(n²)
- **LCB+FMB 双路设计**：交互分支 + 线性压缩分支并行处理再 concat，防止过度交互导致信息丢失
- **feature interaction scaling 这一派的地基之一，想冲 scaling 方向创新必补课**

### 13. HSTU

**论文：** Actions Speak Louder than Words: Trillion-Parameter Sequential Transducers for Generative Recommendations
**链接：** https://arxiv.org/abs/2402.17152 | **来源：** Meta, ICML 2024

#### 解决的问题

大规模推荐系统需处理十亿级动态词汇表、异构特征和每天数百亿流式非平稳数据，传统 Transformer 存在 softmax 归一化丢失数量信息、计算效率低等问题。HSTU 将推荐重新定义为序列转导任务，建立了推荐领域的 scaling law。

#### 核心创新点

- **将推荐重构为生成式序列转导**：用户历史行为和候选 item 交替编排成统一序列，排序任务变为预测 p(a_{i+1}|历史)
- **Pointwise Attention 替代 Softmax**：逐点激活函数 + LayerNorm 替代 softmax。关键洞察：softmax 抹掉了交互次数这一强信号（100 次点击 vs 10 次点击无法区分），pointwise 保留数量信息。HR@10 比 softmax 高 44.7%
- **极简高效架构**：6 个线性层减至 2 个，每层 activation memory 从 33d 降到 14d，比 FlashAttention2 Transformer 快 5.3x-15.2x
- **Stochastic Length（SL）训练**：概率采样截断长序列，80% 稀疏度仅损失 0.2% NE
- **M-FALCON 推理算法**：多候选 item 共享 encoder，285x 模型复杂度仅 1.5-3x 吞吐开销
- **万亿参数 scaling law**：跨三个数量级到 1.5 万亿参数呈幂律增长

#### 不足与局限

- 非序列特征处理粗糙，依赖"隐式捕获"——需要足够长的序列和足够大的模型
- 序列化一切的代价：压缩可能丢失细粒度 cross feature 信息（MTGR 已指出）
- 对序列长度高度依赖，比赛数据序列可能有限
- 1.5 万亿参数部署需 64-256 个 H100，比赛环境无法支撑

#### 对赛题的启发

- **Target-aware 序列编排是关键 idea**：将候选 item 交织进用户历史，每一层都建模"候选与历史的关系"。赛题的 (user, context, target ad) 三元组非常适合
- **Pointwise attention 值得尝试**：CVR 预测中用户行为数量本身是强信号，softmax 会丢掉
- **SL 训练策略可直接使用**：长序列下几乎不损失精度地大幅降低训练成本
- **M-FALCON 推理加速**：多候选共享 encoder，满足延迟要求
- **HSTU 的简化层设计可作为 stackable block**：Pointwise Projection → Spatial Aggregation → Pointwise Transformation
- **但必须补强非序列特征建模**：HSTU 的"隐式捕获"不够，需结合 Wukong/TokenMixer 的显式交互机制
- **很多 2025-2026 工业论文都在继承它的"序列优先 + 可扩展 backbone"视角**

### 推荐的统一 Block 设计

```
输入 Token 序列: [user_profile | item_features | context | cross_features | behavior_seq]

每个 Stackable Block:
┌─────────────────────────────────────────────────────────┐
│ 1. Group-Layer Normalization (MTGR)                     │
│    → 按特征域分组归一化，对齐异构分布                      │
│                                                         │
│ 2. Token Interaction Layer                              │
│    → 方案 A: HeadMixing (MixFormer) — 零参数，延迟最优   │
│    → 方案 B: Token Mixing (RankMixer) — 线性复杂度       │
│    → 方案 C: Cross-Attention (HyFormer) — 表达力最强     │
│                                                         │
│ 3. Per-token / Block-specific FFN (RankMixer/HHFT)      │
│    → S-tokens 共享参数，NS-tokens 独立参数 (OneTrans)    │
│                                                         │
│ 4. Dynamic Masking (MTGR)                               │
│    → non-seq: full attention                            │
│    → seq: causal attention                              │
│    → candidate: self-only attention                     │
│                                                         │
│ 5. Residual + Inter-layer Residual (TokenMixer-Large)   │
└─────────────────────────────────────────────────────────┘
× 2-4 层堆叠（金字塔式逐层减少序列 Query 数量）
      ↓
   CVR Prediction Head (Cross-Entropy Loss)
   + CTR 辅助头 (仅训练)
   + NAL 自监督损失 (InfoNCE)
```

### 14. TWIN — 两阶段长序列兴趣网络

- **来源**: Kuaishou, KDD 2023
- **论文**: "TWIN: TWo-stage Interest Network for Lifelong User Behavior Modeling in CTR Prediction"
- **核心思想**: 两阶段：CP-GSU（SimHash 快速粗检索 top-K）→ ESU（target attention 精排）。将行为特征分为 video-inherent（可预计算缓存）和 cross（压缩为 1D bias），减少 99.3% 计算。
- **对我们的意义**: **高** — 直接解决我们长序列截断问题（domain_d 最长 2394）。第一阶段 hash 检索 top-128 相关行为，再对这 128 个做 target-aware pooling。
- **可借鉴**: (a) 预计算并缓存序列 item embedding; (b) SimHash/LSH 做快速 top-K 检索; (c) cross 特征压缩为 bias

### 15. SDIM — 基于采样的长序列建模

- **来源**: Meituan, CIKM 2022（部署至 2023+）
- **论文**: "Sampling Is All You Need on Modeling Long-Term User Behaviors for CTR Prediction"
- **核心思想**: 用 SimHash 把内积相似度转为 Hamming 距离，O(L) 直接获取用户长序列 embedding，跳过 multi-head target attention。线上 +2.98% CTR。
- **对我们的意义**: **中高** — 比 TWIN 更简单，可作为 truncation 的替代：hash 所有 2394 个 item，采样相关子集。
- **可借鉴**: SimHash 采样作为预处理步骤，替代截断

### 16. UniMixer — 统一混合架构 + Scaling Law

- **来源**: Kuaishou, arXiv April 2026
- **论文**: "UniMixer: A Unified Architecture for Scaling Laws in Recommendation Systems"
- **核心思想**: 将 attention、TokenMixer、FM 统一为 `Global Mixing × Local Mixing` 框架。把规则型 TokenMixer 参数化为可学习矩阵。UniMixing-Lite 用基分解+低秩近似省参数。84.5M params AUC 0.7527 vs RankMixer 135.5M at 0.7493。
- **对我们的意义**: **高** — 我们的 HeadMixing 是固定 TokenMixer。UniMixer 说应该让 mixing pattern **可学习**，低秩分解还能省参数。
- **可借鉴**: (a) 固定 HeadMixing → 可学习 mixing 矩阵; (b) 低秩分解省参数; (c) 温度退火训练

### 17. DCNv3 — 指数阶特征交叉

- **来源**: arXiv 2024
- **论文**: "DCNv3: Towards Next Generation Deep Cross Network for CTR Prediction"
- **核心思想**: L 层实现 2^L 阶交叉（vs DCNv2 的线性增长）。Self-Mask（LN+ReLU，~50% 稀疏度）减半参数同时过滤噪声。Tri-BCE 给子网络差异化监督。仅 1.37M 参数，6 个数据集 SOTA。
- **对我们的意义**: **中** — Self-Mask 可加到 HeadMixing 输出做稀疏化。Tri-BCE 的多 loss 思想与我们的辅助损失实验相关。
- **可借鉴**: (a) Self-Mask 作为 post-mixing 稀疏化层; (b) Tri-BCE 风格差异化监督

### 18. DHEN for CVR — NAL 的正确配方

- **来源**: Meta, WWW 2025 Companion
- **论文**: "On the Practice of Deep Hierarchical Ensemble Network for Ad Conversion Rate Prediction"
- **核心思想**: 扩展 DHEN 到 CVR，自监督 NAL 用 INFO-NCE（90 positive predictions, 20 negatives per positive）。结果 +2.18% AUC。确认 **2 层是 sweet spot**（3 层边际/退化）。序列特征贡献 ~2x 其他特征。
- **对我们的意义**: **高** — 直接解释为什么我们的 NAL 实验失败：配方不对。他们用 INFO-NCE + 特定正负采样比（90:20），不是简单 next-token。也确认了我们 2 层的选择。
- **可借鉴**: (a) NAL 重新实现为 INFO-NCE + 90 pos / 20 neg 采样; (b) 保持 2 层; (c) 序列特征重要性最高

### 19. FuXi-Linear — 时间感知线性 Attention

- **来源**: arXiv Feb 2026
- **论文**: "FuXi-Linear: Unleashing the Power of Linear Attention in Long-term Time-aware Sequential Recommendation"
- **核心思想**: Temporal Retention Channel 独立计算周期性 attention 权重，防止时间和语义信号串扰。Prefill 10x 加速，Decode 21x 加速。1000 长度序列展示 power-law scaling。
- **对我们的意义**: **中高** — 时间独立编码通道新颖且相关：我们序列有隐式时序但目前忽略了。
- **可借鉴**: (a) 分离时间编码通道; (b) 线性 attention 处理时间通道

### 20. Kunlun — 大规模推荐系统 Scaling Law

- **来源**: Meta, arXiv Feb 2026
- **论文**: "Kunlun: Establishing Scaling Laws for Massive-Scale Recommendation Systems through Unified Architecture Design"
- **核心思想**: GDPA（广义点积 attention）、**HSP（层级种子池化）**压缩长序列、滑窗 attention。CompSkip 跳过简单样本，MFU 17%→37%。
- **对我们的意义**: **中高** — HSP 直接适用：先 domain 内池化，再跨 domain 池化，恰好匹配我们 4 domain 结构。
- **可借鉴**: (a) 层级种子池化：domain 内 → 跨 domain; (b) 滑窗 attention 做 domain 内序列建模

### 21. TAAC 2025 — 上届竞赛基线与方案

- **来源**: Tencent Advertising Algorithm Competition 2025
- **关键信息**: 2025 赛题用 SASRec 做 baseline，top 方案在此基础上做生成式推荐。6000+ 参赛队。Transformer 序列建模是预期基础，创新在特征统一和序列建模。
- **对我们的意义**: **高** — 确认 transformer 是预期基础架构，我们的 UniRec-Hybrid 方向正确。
