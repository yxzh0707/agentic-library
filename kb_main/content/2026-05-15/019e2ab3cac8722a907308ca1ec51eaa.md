## Session 2026-04-12 — Full 5-Model Vendor Audit (Claude Code + Codex Joint)

### What was done
- Claude Code 审查 UniRec + HyFormer model.py
- Codex 审查 InterFormer + DeepContextNet（派发后超时，Claude Code 补完）
- OneTrans 已在 Day 0 审查，此次跳过
- 全部 5 个模型的 model.py + __init__.py 配置已审查完毕

### Audit Results

| 模型 | 审查结论 | 主要问题 | 是否可用 |
|------|---------|---------|---------|
| OneTrans | 质量高 | cross feature 压缩（已修复）、shuffle（已修复） | 可用 ✅ |
| UniRec | 质量较高 | dense_dim=16、pairwise_weight=0.25 可能高估 AUC | 可用但需修配置 ✅ |
| InterFormer | 质量较高 | 序列缺 causal mask、dense_dim=16 | 可用但需注意 ⚠️ |
| HyFormer | 质量合格 | 序列缺 causal mask、dense_dim=16 | 需修配置后重测 ⚠️ |
| DeepContextNet | 质量低 | attention mask bug（padding污染CLS）、ReLU截断 | 不可用 ❌ |

### Key findings
- **dense_feature_dim=16 是共性问题**：除 OneTrans（已修为144），其余 4 个模型均为 16。当前排名被不公平配置扭曲
- **序列缺 causal mask 是共性问题**：InterFormer、HyFormer、DeepContextNet 都没有 causal mask，允许未来信息泄漏
- **UniRec pairwise_weight=0.25**：其他模型均为 0，给了 UniRec 额外训练优势。其 AUC 领先可能部分来自 loss 而非架构
- **DeepContextNet 确认有实现 bug**：attention mask 不完整导致 padding token 污染 CLS，加上 ReLU 截断导致 AUC < 0.5。放弃此模型
- **当前架构排名不可信**：需统一配置（dense_dim=144、pairwise_weight 统一）后重跑才是公平比较
- **vendor 代码确认非完全可信**：5 个模型中 1 个有明显 bug，4 个有配置不公平问题

### Next steps (priority-ordered)
1. 统一所有模型 dense_feature_dim=144 + pairwise_weight=0 后重跑排名
2. 验证 domain→sequence 映射正确性（仍然是 P0）
3. 基于公平排名结果选定 1-2 个架构深入迭代
4. 记录审查结论到 Notion

- domain→sequence 映射仍未验证

## Algorithm Review Round 1 — 自研 UniRec 架构决策（2026-04-12）

### 最终方案：UniRec-Hybrid
- B 骨架（7 token + 2 层 MixerBlock）+ A 的 target-aware pooling + 序列保留时序

- 序列截断到 128 丢失长尾信息

## Session 2026-04-13 — Day 5: CRITICAL FINDING - Baseline Noise Dominates

### 最重要发现
**单 seed 结论全部不可信。** 多 seed 验证表明：
- UniRec-Hybrid 无 GLN（之前报告 0.7896）
  - Seed 7:   0.6336
  - Seed 42:  0.7462
  - Seed 123: 0.7058
  - Mean: 0.6952 ± 0.057

**噪声 ±5.7% >> 所有之前 ablation 的 delta：**
- GLN ablation: +0.4% ← 远在噪声内
- Target-Aware: -7.8% ← 勉强超噪声
- Per-token FFN: -4.7% ← 在噪声内
- HeadMixing: -8.5% ← 唯一勉强超噪声
- NAL: -2.7% ← 在噪声内
- Self-Attn: -5.2% ← 在噪声内

### 这意味着
1. 之前的架构排名（包括 HyFormer/OneTrans/InterFormer）可能都是噪声
2. Day 3 的 Ablation "结论" 需要全部多 seed 重做
3. GLN 可能并不真的"有害"，可能只是 seed 幸运
4. HeadMixing 是唯一可能真实有效的组件（勉强）

### Next steps (priority-ordered)
1. 立即停止在 1000 样本上做单 seed ablation，**所有实验强制 3+ seed**
2. 升级 ExperimentLoop：内置多 seed 运行模式，输出 mean±std
3. 升级 QA 机制：检查 delta 是否显著大于 seed 方差，否则标注"可能是噪声"
4. 之前所有"结论"在 Notion 和 domain_hints 上打上 "single-seed, may be noise" 警告
5. 正式数据到了（10x 大小），这些结论需要重新验证

### Earlier Mistake (recorded for memory)
- **I previously (incorrectly) told the user that α=0.10 was "more aggressive positive weighting"**. WRONG.
- The actual code: `alpha_t = alpha * targets + (1 - alpha) * (1 - targets)`. So α=0.10 means positives get weight 0.10, negatives 0.90 — i.e., MORE negative emphasis.
- The implementation is correct (matches torchvision standard). My interpretation of "α aggressive direction" was inverted.
- The empirical result (I-631 < I-630) actually MAKES SENSE under the correct interpretation: less positive emphasis hurts when positives are rare.
- Lesson: when in doubt about loss formula semantics, READ THE CODE before reasoning.

### Why focal loss family fails on our data
- BCE on 5% positive rate already produces a well-calibrated model (sigmoid output ≈ 0.05 baseline).
- Focal weight `(1-p_t)^γ` already strongly emphasizes positives (since model predicts ~0.05 for them, focal_weight ≈ 0.9).
- Adding α further shifts the balance, but in either direction the result is worse than BCE.
- Focal loss was designed for EXTREME imbalance (object detection, ~1:1000). 5% positive rate is in BCE's effective regime.
- **Generalizable rule**: focal loss is not a free improvement; it requires extreme class imbalance to outperform BCE.
