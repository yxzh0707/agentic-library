### IB1. Target-aware temporal encoding for sparse ad sequences

```yaml
- source: tencent_ads_kdd24_practice
  url: https://developer.volcengine.com/articles/7417663816043642906
  title: "KDD'24 | 一文详解腾讯广告推荐算法优化实践"
  date: 2024-09
  primary_topic: PCVR / sequence_modeling / temporal_encoding
  key_mechanism:
    name: TIM / Target-aware Temporal Encoding
    description: >
      对用户点击/转化历史同时编码行为语义、目标语义、行为时序、目标时序。
      腾讯广告落地时同时使用相对位置和时间间隔，把 TIM 输出与 DCN V2/GwPFM
      等特征交互模块拼接；作者特别指出广告点击稀疏时，时间间隔比相对位置更有信息量。
    reported_effect: "微信 pCTR GMV +1.93%"
  applicability_to_kddcup2026:
    score: high
    rationale: >
      TencentGR 有 4.6 天分布漂移，PCVRHyFormer 当前只靠通用序列 token 和位置建模，是否显式加入
      action-target 时间差、跨 domain 时间间隔衰减，是直接相关问题。为什么只让 Transformer 自己学时间？
      稀疏 CVR 场景里，显式时间间隔很可能比绝对位置更稳。
  extractable_prior: "广告 CVR/PCVR 的行为序列应显式提供 target-aware time-gap，而不是只给 position id。"
  cost_to_implement_in_pcvrhyformer: medium
  experiment_candidate:
    suggested_id: I-701
    config_delta: "为每个 domain 序列 token 增加 log1p(abs(t_action - t_target)) bucket embedding；与现有 token embedding 相加或 concat 后线性投影；先不改主干。"
    predicted_p_above_815: 0.24
  conflicts_or_overlaps_with_existing:
    - "overlaps: domain_hints 中 LONGER/OneTrans 的时间差与序列边界 prior"
    - "compatible: PCVRHyFormer 2-layer d_model=64，不需要加深模型"
```

### IB2. Visual/semantic ID replacement via LSH + hybrid N-ary encoding

```yaml
- source: tencent_ads_kdd24_practice
  url: https://developer.volcengine.com/articles/7417663816043642906
  title: "KDD'24 | 一文详解腾讯广告推荐算法优化实践"
  date: 2024-09
  primary_topic: feature_encoding / cold_start / PCVR
  key_mechanism:
    name: Visual Semantic ID + Multi-radix Numerical Encoding
    description: >
      腾讯广告认为随机/自增广告 ID 语义弱，使用预训练视觉模型提取广告素材 embedding，
      再用 LSH 转成保留视觉相似度的数值，最后通过多进制编码转为可学习 embedding。
      同文还提出 SEE，把外部 GNN/LLM embedding 的相似度先验编码成可学习数值特征，而不是直接拼外部 embedding。
    reported_effect: "视频号 pCVR GMV +1.13%；新广告 +1.74%；朋友圈/视频号 pCTR GNN 相似度编码 GMV +1.21%/+0.59%"
  applicability_to_kddcup2026:
    score: high
    rationale: >
      比赛数据未必有图像，但有大量高基数 item/ad/content ID。当前 I-602 ID dropout 已说明高基 ID 很敏感。
      如果 item/content 侧存在稀疏长尾，直接依赖原始 ID 会弱化冷启动和相似 item 泛化。能否用已有 dense/content 特征构造
      semantic bucket ID，是一个低侵入实验。
  extractable_prior: "高基随机 ID 不应裸用；应把内容相似度或外部 embedding 相似度离散成可学习 bucket，以保留语义先验。"
  cost_to_implement_in_pcvrhyformer: medium
  experiment_candidate:
    suggested_id: I-702
    config_delta: "用 item/content dense features 做 random projection LSH 或 kmeans bucket，新增 semantic_item_bucket embedding；先只加 item 侧，不替换原 ID。"
    predicted_p_above_815: 0.20
  conflicts_or_overlaps_with_existing:
    - "overlaps: I-602 ID dropout / high-card ID regularization"
    - "risk: 如果 dense/content features 本身是泄漏或噪声，semantic bucket 会放大噪声"
```

### IB3. Asymmetric multi-embedding for multi-task conversion disentanglement

```yaml
- source: tencent_ads_kdd24_practice
  url: https://developer.volcengine.com/articles/7417663816043642906
  title: "KDD'24 | 一文详解腾讯广告推荐算法优化实践"
  date: 2024-09
  primary_topic: multi_task / PCVR / negative_transfer
  key_mechanism:
    name: AME / STEM-AL
    description: >
      对多转化类型或多场景任务，不只共享一个 embedding 表；同时学习共享和任务特定 embedding。
      AME 固定少量 embedding 表，并用不同维度如 16/32/64 做非对称容量路由，缓解大任务压制小任务。
      STEM-AL 在辅助学习中让主任务 embedding 只受主任务反传，共享 embedding 才接收辅助任务反传。
    reported_effect: "朋友圈/公众号 pCVR GMV +4.2%/+3.9%；小程序 pCTR 主任务 CTR +1.16%"
  applicability_to_kddcup2026:
    score: high
    rationale: >
      TAAC 是 PCVR，但 label 或场景可能隐含多个转化/渠道/域。我们当前若把 domain_a/b/c/d 或多个行为目标压进单表，
      可能会出现任务兴趣纠缠。是否应该让不同 domain 或 label_type 有专属小容量 embedding？这正对“分布漂移 + 多域序列”的核心风险。
  extractable_prior: "多域/多目标 CVR 不要只靠共享 embedding；小任务需要受保护的低容量专属表或梯度隔离。"
  cost_to_implement_in_pcvrhyformer: high
  experiment_candidate:
    suggested_id: I-703
    config_delta: "按 domain 或 conversion group 增加 shared + task-specific embedding adapter；主 PCVR loss 更新主表，辅助/domain heads 更新共享表；先做 2 表版本。"
    predicted_p_above_815: 0.16
  conflicts_or_overlaps_with_existing:
    - "overlaps: MTGR/PLE 多任务 prior，但这是腾讯广告博客层面的工程落地解读"
    - "risk: 架构改动较大，必须先小样本 smoke + latency profile"
```

### IB4. Lifelong sequence retrieval + impression-negative Next Action Loss

```yaml
- source: pinterest_engineering_transactv2
  url: https://medium.com/pinterest-engineering/next-level-personalization-how-16k-lifelong-user-actions-supercharge-pinterests-recommendations-bd5989f8f5d3
  title: "Next-Level Personalization: How 16k+ Lifelong User Actions Supercharge Pinterest’s Recommendations"
  date: 2025-06
  primary_topic: sequence_modeling / aux_loss / long_sequence / serving
  key_mechanism:
    name: TransActV2 NN selection + impression-based NAL
    description: >
      对每个候选 item，只取最近 r 个行为和 lifelong/realtime/impression 序列中与候选最相似的 top-K 行为；
      进入一个 2 层 Transformer，d_model=64，FFN=32。辅助目标使用 Next Action Loss，
      且曝光未互动样本比随机负样本更有效。
    reported_effect: "offline Top-3 Repin Hit +13.31%，Hide Hit -11.25%；online Repin +6.35%，Hide -12.8%，time spent +1.41%；p99 model latency -75%~-81%"
  applicability_to_kddcup2026:
    score: high
    rationale: >
      这篇和 PCVRHyFormer 形态高度接近：2 层 Transformer、d_model=64、长序列、工业排序。
      关键问题不是“更深 Transformer”，而是“给每个候选喂哪些历史 token”和“负样本是否来自真实曝光”。
      我们已有 NAL 负结果，但之前可能用了随机负样本或权重不当；Pinterest 的经验提示应优先试 impression-negative/同批曝光负样本。
  extractable_prior: "长序列排序的增益来自 candidate-aware history selection + 曝光负样本 NAL，而不是盲目扩大 max_seq_len。"
  cost_to_implement_in_pcvrhyformer: medium
  experiment_candidate:
    suggested_id: I-704
    config_delta: "在每条样本内按 target item/content embedding 相似度选 topK 历史 token + recent r；NAL 负样本改为同 batch 曝光未转化/未点击样本；NAL weight 从 0.03/0.05 网格起步。"
    predicted_p_above_815: 0.28
  conflicts_or_overlaps_with_existing:
    - "conflict: domain_hints 里 NAL weight=0.3 单次负结果；本条要求低权重 + 曝光负样本，不是重复原实验"
    - "overlaps: HeadMixing/target-aware pooling 是现有强 prior"
```

```yaml
- source: google_research_youtube_music

  title: "Transformers in music recommendation"
  date: 2024-08

    name: Transformer over user actions blended with existing ranker
    description: >
      YouTube Music 将用户行为 token 化：动作意图、播放比例、距上次行为时间、artist/language 等 metadata、
      track embedding。Transformer 编码历史动作和当前上下文，再与已有 ranking model 输入融合，多目标联合训练。

    score: high

      TencentGR 只有 4.6 天，短期上下文可能压过长期偏好。我们需要问：某个历史行为在当前候选和当前时间段下还相关吗？

  conflicts_or_overlaps_with_existing:
```

```yaml
- source: netflix_techblog_foundation_rec

    name: Interaction tokenization + multi-token prediction + metadata cold-start
    description: >

      device/time/content metadata 等关键信息；用 sparse attention 和 sliding window 兼顾长历史和低延迟。
      目标上不只 next-token，还考虑 multi-token prediction，避免只优化眼前下一步。
```

## Summary

最值得 follow-up 的是三条：第一，腾讯 TIM 的 target-aware time-gap，成本中等、和 4.6 天漂移强相关；第二，Pinterest TransActV2 的 candidate-aware history selection + impression-negative NAL，它直接对应我们 2 层、d_model=64 的 PCVRHyFormer，且能解释旧 NAL 负结果为什么不能一票否决；第三，腾讯 semantic ID/SEE，可和 I-602 的高基 ID dropout 形成组合。当前不值得投入的是完整 foundation model、生成式 slate 推荐、强化学习广告预算分配，因为比赛是单模型 CVR/PCVR AUC，数据和延迟约束不支持重型路线。NISE 非点击样本方向很诱人，但目前没有抓到具体技术描述，不能据标题下注。
