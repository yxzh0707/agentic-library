# TAAC 2026 系统全景（通俗版）

> 面向队友的完整系统说明，不需要 ML 背景也能看懂核心逻辑。
> 最后更新：2026-04-16

---

## 一、我们在做什么

**一句话**：预测用户看到一个广告后，会不会真的去买/下载/注册（CVR = 转化率预测）。

```
输入：用户信息 + 广告信息 + 用户历史行为
输出：0~1 的概率（越接近 1 = 越可能转化）
评分：AUC（预测排序准不准）
约束：只能用 1 个模型，不能多个模型投票（禁止 ensemble）
```

---

## 二、数据长什么样

官方给的是一张 **120 列的大表**（parquet 格式），每行是一个"用户看了一个广告"的记录：

```
┌─────────────────────── 基础信息（5 列）─────────────────────────┐
│ user_id | item_id | timestamp | label_type | label_time        │
│  用户    | 广告     | 时间       | 有没有转化   | 转化时间          │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────── 用户特征（56 列）────────────────────────┐
│ user_int_feats_0 ~ _45  (46 列)  → 用户的整数属性（如地区、年龄段）│
│ user_dense_feats_0 ~ _9 (10 列)  → 用户的连续属性（如活跃度得分） │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────── 广告特征（14 列）────────────────────────┐
│ item_int_feats_0 ~ _13  (14 列)  → 广告的属性（如类别、品牌）     │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────── 行为序列（约 45 列）─────────────────────┐
│ domain_a_seq_0 ~ _N     → 用户在"领域 A"的历史行为序列           │
│ domain_b_seq_0 ~ _N     → 用户在"领域 B"的历史行为序列           │
│ domain_c_seq_0 ~ _N     → 用户在"领域 C"的历史行为序列           │
│ domain_d_seq_0 ~ _N     → 用户在"领域 D"的历史行为序列           │
│ （每个 domain 代表一类广告行为，序列最长可达 2394 条）              │
└─────────────────────────────────────────────────────────────────┘
```

## 三、流水线全景

```
官方数据（120 列 parquet）
    ↓
 ① 门卫检查 ── schema_validator.py
    "列名对不对？数量对不对？"
    ↓
 ② 翻译官 ── flat_reader.py
    "把 120 列表格翻译成模型能吃的 tensor 格式"
    ↓
 ③ 大脑 ── unirec_hybrid.py
    "7 个摘要 → 互相讨论 → 输出转化概率"
    ↓
 ④ 教练 ── loop.py
    "训练大脑 + 检查质量 + 记录成绩 + 建议下一步"
    ↓
 ⑤ 交卷 ── submit_round1.py
    "推理 → predictions.csv → 打包 → 上传"
```

## 四、大脑的工作原理（UniRec-Hybrid）

### 核心思想

模型本质上在判断：**"这个用户"和"会转化的用户群体"有多像。**

但用户不是一个简单标签，而是 120 列特征 + 4 条行为序列。模型需要先"读懂"用户，再做判断。

### Step 1：压缩 — 把 120 列变成 7 个"摘要"

```
120 列原始数据
    ↓ 分组压缩
7 个 token（每个是 128 维的向量）

Token 1 "用户是谁"     ← 46 个用户整数特征取加权平均
Token 2 "用户长啥样"    ← 10 个用户连续特征做线性投影
Token 3 "广告是什么"    ← 14 个广告整数特征取加权平均
Token 4 "用户在 A 领域干了啥" ← domain_a 行为序列做注意力池化
Token 5 "用户在 B 领域干了啥" ← domain_b
Token 6 "用户在 C 领域干了啥" ← domain_c
Token 7 "用户在 D 领域干了啥" ← domain_d
```

**为什么是 7 个？** 不是拍脑袋定的，是官方数据结构决定的 — 3 类非序列特征 + 4 个 domain 序列 = 7 个自然分组。

**Target-Aware Pooling（最精妙的部分）**：

普通做法：用户 2000 条历史行为取平均 → 丢失"哪些行为和当前广告相关"
我们的做法：用"当前广告"做问题，去行为序列里找最相关的行为

```
当前广告 = 游戏 App

用户行为 = [游戏A(权重0.4), 外卖App(0.05), 游戏B(0.35), 新闻App(0.02), ...]
            ↑ 高权重                           ↑ 高权重

→ 最终摘要主要反映"游戏偏好"，而非"新闻偏好"
→ 去掉这个组件 AUC 下降 7.8%，是第二重要的组件
```

### Step 2：讨论 — 让 7 个摘要互相交流

7 个 token 单独看各有信息，但**关系**才是关键：
- "用户爱玩游戏" + "广告是游戏" → 强转化信号
- "用户爱玩游戏" + "广告是服装" → 弱信号

**HeadMixing（零参数洗牌）**：
```
洗牌前: [用户.前半维度, 用户.后半维度] [广告.前半维度, 广告.后半维度]
洗牌后: [用户.前半, 广告.前半]         [用户.后半, 广告.后半]
         ↑ 同维度对齐了，交叉模式更容易被发现
```

不增加新参数，只是重新排列组合。去掉后 AUC 下降 8.5%，是最重要的组件。

**Per-token FFN（分级服务）**：
- Token 1/2/3（用户/dense/广告）各有**独立**加工网络 → VIP 专属服务
- Token 4/5/6/7（4 个 domain）**共享**一个加工网络 → 普通窗口

为什么这么设计？用户、广告、dense 特征性质差异很大，需要独立处理；4 个 domain 结构相似，可以共享。

### Step 3：投票 — 输出最终概率

```
7 个 token × 128 维 = 896 维大向量
    ↓ 两层线性网络
1 个数字
    ↓ sigmoid 函数
0.73 = "73% 概率会转化"
```

### 这个架构是怎么来的

不是照搬别人的，经历了 3 个阶段：

```
阶段 1：从社区框架选种子
  → 5 个模型公平比较，UniRec 排第一

阶段 2：4 轮算法评审自研架构
  → 3 个 Agent 独立提案 → 交叉审查 → Red Team 攻击 → Judge 收敛
  → 最终：Agent B 的轻量骨架 + Agent A 的 Target-Aware Pooling
  → 命名 UniRec-Hybrid

阶段 3：Ablation 实验验证
  → 去掉 HeadMixing: -8.5% → 保留
  → 去掉 TargetAware: -7.8% → 保留
  → 去掉 PerTokenFFN: -4.7% → 保留
  → 去掉 GLN: +0.4% → 去掉反而更好！
  → 最终版：UniRec-Hybrid 无 GLN
```

## 五、教练的工作机制（实验闭环）

不是"训练一次就交卷"，而是一个自动化闭环：

```
设计实验
    ↓
训练模型（最多 10 轮，连续 3 轮不进步就早停）
    ↓
自动 QA 检查 ←── 5 项检查
    │  AUC < 0.5？ → 预测可能反了
    │  AUC > 0.95？→ 可能数据泄漏
    │  过拟合严重？ → val/train loss 比值太大
    │  NaN？       → 训练崩了
    │  矛盾？      → 与已知知识冲突
    ↓
记录到 manifest.json（实验档案）
    ↓
自动更新 domain_hints.md（知识库）
    ↓
自动触发论文检索（如果实验涉及已知关键词）
    ↓
建议下一步
    │  AUC 提升 > 0.3%？→ 围绕改动做 ablation
    │  AUC 下降？       → 回滚
    │  原地打转？       → 换方向
    ↓
下一个实验...
```

**断路器（防止无限循环）**：
- 最近 3 次实验 AUC 差距 < 0.001 → 停下分析
- 同一个错误出现 2 次 → 先找根因再重试
- 每 session 最多 8 个实验

## 六、知识体系（三层架构）

```
第一层：铁律（永远不违反）
  "不能用 ensemble"
  "训练/验证必须按时间切分"
  "指标是 AUC"

第二层：强先验（可被实验推翻）
  "HeadMixing 是必要组件" ← 已验证（-8.5%）
  "GLN 有效" ← 已被推翻（去掉反而好）
  "NAL 有帮助" ← demo 失败，待正式数据重试

第三层：本地发现（实验产出的新知识）
  "多 seed 噪声 ±5.7% 远大于所有 ablation delta"
  "Self-Attention 在 1000 样本严重过拟合"
```

知识流动：论文 → 强先验 → 实验验证 → 升级/推翻/补充

## 七、元思考框架（暗室碰撞实验校准）

最高层级 — 不是"怎么做实验"，而是**"怎么决定做什么实验"**。

通过在历届 TAAC 赛题（2017/2020/2025）上仿真推演，发现并修正了推理偏差：

### 修正了 5 个错误默认行为

| 旧行为 | 校准后 | 来自哪一轮 |
|---|---|---|
| 构造特征→直接扔模型 | 先做统计分析→筛选→再入模 | Round 1 (2017) |
| 拿到任务→直接选模型 | 先问"能否重新定义问题？" | Round 2 (2020) |
| 数据清洗随便做 | 占 40% 注意力 | Round 1 (2017) |
| 成本高→立刻淘汰 | 延迟淘汰到有数据支撑 | Round 3 (2025) |
| 规则一刀切 | 每条规则附适用条件 | Round 3 (2025) |

### 四层嵌套的学习系统

```
第一层（内循环）：模型学 "用户会不会转化"          → 分钟级
第二层（中循环）：实验闭环学 "什么改动有效"         → 小时级
第三层（外循环）：知识积累学 "什么方向值得探索"      → 天级
第四层（元循环）：暗室实验学 "怎么想才不会犯系统性错" → 一次性
```
