# I-646_chorus_cvr_funnel

```yaml
id: I-646
name: chorus_cvr_funnel
status: ready_for_taiji
base: experiments/I-625_gap_features/code/  (forked, BCE -> dual-head ESMM/chorus)
fork_base: "experiments/I-625_gap_features/code/"
prior:
  expected_lb_auc: 0.826
  range: [0.821, 0.832]
  p_improve_over_baseline: 0.50
  baseline_lb_auc: 0.822863  # I-625

amp_compile_caveat: "Inherited from I-625 base (amp+compile always on)."

rationale:
  - 元规则 forward-looking 双条件双过 (data_understanding_v2):
    (a) NEW signal: label_type==0 (exposure-only) and ==1 (click-not-converted)
        have NEVER been used as supervision in any of our 17 experiments —
        we always collapsed them to "negative" in BCE. ChorusCVR uses all
        three labels via dual-head ESMM-style decomposition.
    (b) OOV-safe: funnel labels are sample-level, not identity-bound. No
        item_id / user_id binding.
  - Cross-validated by 2025-2026 lit (`知识库拓展/2025-2026_findings.md`):
    ChorusCVR (WSDM 2026, Kun Gai/Guorui Zhou, arXiv:2502.08277) +
    ESCIM (ICDM 2025) both validate funnel-hierarchical supervision.
  - Mechanism distinct from PWiseR/Combined-Pair (Pattern B reweighting,
    KILLed): pairwise compares same-batch samples in binary y; chorus
    introduces a SECOND TASK (P(click)) the model must jointly learn.
    The auxiliary head's gradient flows back through the shared encoder,
    producing different representations than BCE-only.

design:
  multi_head:
    - clk_head: predicts P(click | impression) trained on y_clk = (label_type >= 1)
    - cvr_head: predicts P(conversion | click) trained on y_cvr = (label_type == 2)
                with selection mask y_clk == 1.
  loss:
    L = BCE(logits_clk, y_clk)
        + chorus_lambda * masked_BCE(logits_cvr, y_cvr; mask=y_clk)
    chorus_lambda default 1.0.
  inference_score: sigmoid(logits_clk) * sigmoid(logits_cvr)   # ESMM
  fallback: when --loss_type bce (default), I-646 behaves identically
            to I-625 — the chorus head is built but not used in loss.

changes (vs I-625):
  - dataset.py: result dict adds 'label_type' (int64 per row).
  - model.py:
      * __init__ accepts use_chorus_head (default False).
      * When True, add self.clsfier_clk = nn.Linear(d_model, 1).
      * forward() returns (logits_cvr, logits_clk) tuple when enabled.
  - trainer.py:
      * loss_type='chorus' branch computes L = BCE_clk + lambda * BCE_cvr_masked.
      * AUC eval uses sigmoid(logits_clk) * sigmoid(logits_cvr).
  - train.py:
      * --loss_type choices add 'chorus'.
      * --chorus_lambda flag (default 1.0).
  - infer.py:
      * If train_config['loss_type']=='chorus': score = clk * cvr.
  - run.sh: passes --loss_type chorus --chorus_lambda 1.0.

new_dense_params: ~65  # one extra Linear(d_model=64, 1) head
architecture_constraint: none new (no new tokens, num_ns unchanged from I-625)

decision_thresholds:
  promote_if: "leaderboard_auc >= 0.825"
  neutral: "0.822 <= leaderboard_auc < 0.825"
  kill_if: "leaderboard_auc < 0.822"

next_actions:
  promote:
    - First +EV on funnel-supervision axis after PWiseR/focal closure.
      Sweep chorus_lambda ∈ {0.5, 1.0, 2.0}.
    - Stack with I-643 cate OOF (orthogonal: I-643 = features, I-646 = loss).
  neutral:
    - Try ESCIM-style counterfactual augmentation on label_type==0 rows.
    - Or add a third head for direct label_type multi-class.
  kill:
    - Funnel decomposition does not transfer; label_type==0 may carry no
      additional signal beyond what BCE already extracts.
    - Pivot to semantic IDs (RQ-KMeans) as next NEW signal axis.
```
