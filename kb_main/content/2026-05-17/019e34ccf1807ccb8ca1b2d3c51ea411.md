## Rationale

I-643 is still the best confirmed base. I-651 showed that adding more cate
fields hurts, and I-653 showed UserPair hurts. The cleanest remaining card is
not another feature stack; it is tuning the one cate signal that already won.

I-643 used `item_heat_alpha=100.0`. I-655 lowers it to `30.0`, meaning the
model trusts category-specific CTR/CVR statistics more and shrinks less toward
the global prior.

## Changes vs I-643

- `run.sh`
  - adds `ITEM_HEAT_ALPHA="${ITEM_HEAT_ALPHA:-30.0}"`;
  - passes `--item_heat_alpha "${ITEM_HEAT_ALPHA}"`;
  - logs I-655 identity.
- No code-path, architecture, tokenizer, loss, or feature-field changes.

## Risk Audit

- Positive path: cate-level statistics are real and alpha=100 was too
  conservative.
- Main risk: alpha=30 overfits noisy cate buckets and drops below I-643.
- Attribution is clean because this is a single-hyperparameter change.

## Decision Thresholds

- promote if `leaderboard_auc >= 0.8250`;
- neutral if `0.8240 <= leaderboard_auc < 0.8250`;
- kill if `< 0.8240`.

## If Result

- If promote: run alpha interpolation (`50` or `60`) before stacking more.
- If neutral: run alpha=300 only if there is spare capacity.
- If kill: keep I-643 alpha=100 and do not lower smoothing further.
