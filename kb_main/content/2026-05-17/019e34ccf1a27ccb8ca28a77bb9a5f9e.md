## 三、可借鉴候选 (5 个, 已加入 dreamwalk 队列)

### 🥇 GLN (Group-Layer Normalization)

- **KB 描述**: Tier-1 Step 2, "+0.1~0.3% AUC（几乎零代价）"
- **我们没尝试** — 加入 dreamwalk #13 候选
- **实现量**: ~20 行
- **触发条件**: I-674 LB 出后无论 outcome → 派 I-670+GLN

### 🥈 OneTrans NS 独占参数

- **KB 描述**: "S-tokens 共享参数, NS-tokens 独占参数 (OneTrans 风格)"
- **我们现状**: NS shared (RankMixerNS)
- **实现量**: ~200 行 (大改造)
- **触发条件**: I-674 KILL → 大改造方向

### 🥉 MTGR Dynamic Masking

- **KB 描述**: Tier-3 创新点之一
- **我们没尝试** — 加入 dreamwalk 候选
- **跟 DropPath/CutMix 不同 axis** (mask 是 zero, drop 是 skip)
- **实现量**: ~50 行

### Tier-2: ESMM/PLE 多任务 CTR + CVR

- **KB 描述**: "+0.3~1.0% AUC"
- **风险**: 需要 CTR label, 我们 schema 是否有? Need audit
- 如果 label_type 含 click signal → 可用作 CTR proxy
- **实现量**: ~80 行

### Tier-2: Next Action Loss 辅助

- **KB 描述**: Tier-1 Step 4, "+0.1~0.3% AUC"
- **跟我们独家 label_time aux 不同**: 这个是预测下一个 action_type
- **实现量**: ~50 行

## 五、KB 不直接适用的部分

| KB 推荐 | 不适用原因 |
|---|---|
| MTGR → OneTrans 完整路径 | 架构大改成本 vs 8 天剩余时间不匹配 |
| Scaling Law 论文奖路线 | 时间不够跑 3 档模型 + 曲线绘制 |
| Sample-Is-Feature scaling | 跟我们当前 NS RankMixer 设计冲突 |
| KV Cache 工程实现 | 比赛单 forward, 不需要 cross-request cache |

## 六、KB 没回答我们核心痛点

### 痛点 1: valid AUC ≠ LB AUC (15 次确认)

- KB 提 ESMM 多任务有 "+0.3-1.0%"，但未讨论 valid→LB 转移
- KB 提 KD "AUC 接近大模型"，但同样未讨论转移
- **我们独家发现 (KB 未含)**: 测试集是 1.5h 单窗口，导致 reweighting 类策略 5/5 KILL (Pattern B)

### 痛点 2: stacks 不可加性

- KB 没提 (倾向推荐多机制 stack)
- **我们 + 论坛 SPHINX 双独立印证**: I-672 stack KILL + SPHINX 全 stack 掉分
