## A. Ado佬 (微信公众号 / 群聊, "腾讯广告算法大赛 Day x")

> 原作：Seed（已关注），289 ❤ 454⭐ 20 💬

### A.1 当前方案 (4 条)

1. **user dense feats 将 ue 分离出来，其他跟 int pair 加权**
2. 建模为 **raw embedding + 序列 merge + fafe + DIN + mlp**
3. 时间特征补充
4. 全程 vibe coding

### A.2 问题点 (5 条)

1. **id 特征没用**：uid 训练集和测试集都是只有一条 instance 且无交集（不懂为啥这样设计）。item id 线下 auc 虚高，线上掉，估计也是分布问题。**id 特征在精排没用真的难绷，搞了好多版** 🥲
2. **随机种子复现**：看固定了种子还是有随机性，问 opus 说是 cuda determine 没固定 + sdpa 算子 + iterable 的问题，还没确定
3. **验证集划分**：正常来说上按 timestamp 划分选最佳参数再全量最好，可以训完最近的数据。但目前先按随机划分实验
4. **pure model 建模**：主流的 rankmixer/onetrans/hyformer/mixformer 都基本为了提 mfu 改成 pure model，没有太多精细的传统派小结构建模，但试了下都掉分，可能数据量不够
5. **长序列**：seqc feat47 跟 itemid 是一样的，做不做 match 特征都掉分

### A.3 跟我们项目独立验证一致

| Ado 观察 | 我们对照 | 状态 |
|---|---|---|
| id 特征不转移 | I-608/I-635/I-503/I-666 KILL 同模式 | ✅ 一致 |
| item id 线下虚高线上掉 | 我们 13/14 次 val↑/LB↓ | ✅ 一致 |
| id 在精排没用 | 我们 axis-closure 同样判定 | ✅ 一致 |
| pure model 改造都掉分 | 我们 "不换 backbone" 决策 | ✅ 一致 |
| 长 seq seqc feat47 ≈ itemid 做 match 也掉分 | item_id sparse KILL 一致 | ✅ 一致 |

### A.4 我们可借鉴的部分

- **user_dense 拆 ue + 其他 int-pair 加权** → 已实现为 I-674 (Ado-style)，LB 待终态
- **89-91 没加**：经我们 schema audit 确认是 user_dense_feats_89/90/91 (10 维 quantile)，I-674 默认 drop

## B. SPHINX V7.6 (小红书网页版, "算子化与选择融合改进")

> 第三方完整方案 (TAAC v7.6 TQF 结构修正版)

### B.1 总体目标

- v7.6 是 v7.3 诊断基础上形成的 TQF 结构修正版
- **目标不是扩参，而是激活 TQF 的证据选择、上下文改写与时间调制能力**
- v7.6 将 Selective Summary 升级为 **Domain Evidence Router**，根据 query evidence / NS context / 时间上下文 / domain 特征**动态选择可靠序列源**，而不是简单平均融合
- v7.6 将时间信息从末端 logit residual **前移到 query 与 TQF 交互过程中**，使时间成为影响读取方式、domain 选择和排序分数的条件变量
- 训练侧同步调整 **temperature / entropy penalty / gamma 初始化 / warmup / cosine annealing**，缓解 loss plateau，同时避免 router 早期过尖
- v7.6 标志着 TQF 从"稳定融合模块"转向"**动态证据推理算子**"

### B.2 架构 7 个核心机制 (来自图)

| 机制 | 作用 | 我们项目对照 | 借鉴价值 |
|---|---|---|---|
| 1. **DenseGroupProjector** | user_dense 拆 emb/stat/quantile 三路 | ❌ 没拆 (一锅炖 623 维) → **我们的 I-674 = 这一片 + Ado int-pair gate** | 🟢 已实施 |
| 2. **TimeContextEncoder** | per-domain masked mean → MLP → z_t (B, D) | ⚠️ 只有 seq-time Fourier (I-605) | 🟢 高 |
| 3. **QueryGenerator with z_t** | query 受时间条件化 (g = [user_ns, A, s_B, s_C, s_D; z_t] → MLP) | ❌ | 🟡 中 |
| 4. **per-domain SemanticSeqEmbedder** | item + action + stat + time + domain_type embedding | ⚠️ 单 RankMixerNS | 🟡 中 |
| 5. **Domain-wise Q Decoding** (CrossAttn) | per-domain query 主动选证据 | ❌ | 🟡 中 |
| 6. **Sharpened Selective Cross Summary** | τ=0.45 sharpened softmax + entropy penalty in train | ❌ | 🟢 **下一轮候选** |
| 7. **Stronger γ Write-Back + Strong Time Residual** | logit += y_t · MLP([h⊕z_t⊕h²⊕h·z_t]), y_t init 0.05 | ❌ (I-657 只 1D 校准) | 🟢 **下一轮候选** |

### B.3 训练侧调整

- Sharpened Selective Summary (τ=0.45, score + domain bias + entropy penalty)
- 4-head ≈ 128 Mainline (cross-attention heads 2~4)
- Query Self-Refinement (self-attn on Q [0; 16-D] in NS mixer)
- Stronger NS / Time Residuals (time residual 0.05, 4D interaction input)
- Train Diagnostics + Cosine Restart (0.5 epoch x H_ns/time/D logging)

### B.4 论坛附加信号 (用户告知)

**"SPHINX 单拿 1-2 个机制涨千分位，一起做反而掉分"** — 跟我们 I-672 stack-fail (-0.0027) 双独立印证 **stacks 不可加性** [[feedback_stacks_not_additive]]。

### B.5 我们采纳策略

- **不搬全 7 机制** (会掉分)
- I-674 已用了 #1 DenseGroupProjector
- 下一轮 candidate：#6 Sharpened Routing 或 #7 Strong Time Residual (单机制独立测)
- 训练侧 entropy penalty / temperature 待 attention 类机制成功后再调
