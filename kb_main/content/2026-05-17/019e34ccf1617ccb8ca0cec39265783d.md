## Config delta vs I-601

```
+ --id_dropout_prob 0.3
+ --id_dropout_threshold 10000
```

`split_mode timestamp` is inherited from I-601 (the run.sh starting point).

`dataset.py` and `train.py` extend the I-601 versions with two new
PCVRParquetDataset constructor kwargs: `id_dropout_prob` and
`id_dropout_threshold`. Validation datasets pass-through default
`id_dropout_prob=0.0` so dropout is training-only.

## Mechanism (revised after Codex review)

During training only, each row independently rolls a coin per ID-like
feature column whose `vocab > id_dropout_threshold`; with probability
`id_dropout_prob` the column is zeroed (= `padding_idx` of the matching
Embedding) before the batch leaves the dataset. Validation, evaluation,
and test inference all bypass dropout.

**Codex correction**: this experiment does NOT primarily attack
sparse-Embedding memorization — the cold-restart hook
(`--reinit_sparse_after_epoch=1`, proven load-bearing in I-503) already
wipes high-cardinality Embeddings every epoch end. What I-602 actually
attacks is the **dense-parameter co-adaptation to the ID channel**:
attention, projection, MLP, and head weights persist across epochs and
can learn to lean on per-row IDs even though the Embeddings are reset.
Forcing 30% of rows to have zeroed IDs trains those dense weights to
function without that signal.

## Why this experiment

2026-04-30 diagnostic findings:
- user_id 100% non-recurring (every row = unique user) → ID Embeddings carry zero transfer signal at test time
- item D9-vs-D0 overlap = 1.8% → high-cardinality item / content IDs in test are mostly unseen
- Conversion rate variance 313% over the 4.6-day train window → severe in-window distribution shift
- 99% of the 240M-param budget lives in sparse Embeddings; making the model less reliant on ID lookups potentially unlocks better use of low-card / dense / sequence features

## Audit log expectation

At training start the dataset prints how many user_int / item_int / per-seq-domain features will actually be touched by id_dropout (i.e. `vocab > id_dropout_threshold`). If this number is suspiciously low (e.g. < 5 total) the threshold is too high and the experiment is shadow-boxing already-skipped features. Stop and re-run with smaller threshold.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| `p=0.3` too aggressive (drops ID signal that DOES transfer for the 1.8% overlap items) | Medium | First-run point; sweep p∈{0.1, 0.5} only if first run is positive |
| Threshold 10K still misses meaningful features | Medium | Audit log shows affected feature count; adjust if < 5 |
| Train/test feature distribution mismatch (model sees 30% zeros at train, 0% at test) | Low | Padding embedding is initialized to and stays zero; test never falls back on padding behavior |
| Codex challenge identified concern: experiment may primarily probe dense params, not sparse | Acknowledged | Either way, learning rate per-row regularization is meaningful |

## Outcome

**Mixed signal. Right comparator matters.**

| Comparator | Δ leaderboard | Reading |
|---|---|---|
| vs baseline-0 (0.81147) | **-0.00781** | Looks bad in isolation |
| vs I-601 (0.79927, same timestamp split) | **+0.00439** | id_dropout itself is positive |

Because I-602 inherited `--split_mode timestamp` from I-601, the proper apples-to-apples comparator is I-601, not baseline-0. Under that frame, **id_dropout p=0.3 t=10K added +0.0044 leaderboard** — slightly above the conservative `+0.001~+0.003` prediction in the eval-submission template, well below the original `+0.005~+0.015` Job Description prediction.

**Codex's challenge was right**: this experiment primarily regularized dense-parameter co-adaptation to the ID channel (cold restart already handles sparse Embeddings every epoch). Net leaderboard win on top of cold restart confirms the dense-params angle.

**Inference time** dropped to 211.64s (vs baseline-0's 323.61s, I-601's 320.82s) — likely platform variance, not a real systematic effect, since id_dropout is training-only and inference path is identical.

## Next-step decision points

- p sweep (p∈{0.1, 0.5}) is now justified — primary effect is positive
- But unsweep until I-601's timestamp-split mystery is resolved: if timestamp val is itself misleading, all I-60X comparisons are confounded
