## What actually happened

This Taiji submission was labeled `I-657 mlplatt_monocal` and described as
"I-643 baseline + MLPlatt residual calibration head ... user_dense → context
MLP → detached raw logit → MonoMLP → residual back to raw ...". However:

**Verified via platform code dump 2026-05-10 12:32**:
- `taiji-output/code/angel_training_..._0afb92ff/files/model.py` — `grep mlplatt|MLPlatt` returns 0 hits
- `taiji-output/code/angel_training_..._0afb92ff/files/trainer.py` — `betas=(0.9, 0.98)` unchanged from I-643
- cfg dump in eval log line 153 — no `use_mlplatt` / `mlplatt_*` fields present

The submitted code was byte-identical to I-643. The fork dir
`experiments/I-657_mlplatt_monocal/code/` contained only the design docs
(meta.md / IMPLEMENTATION_PLAN.md / codex_challenge_brief.md, all v2
post Codex challenge). The actual MLPlatt code (~185 lines across model.py /
trainer.py / train.py / infer.py / run.sh) was never written before
packaging the submission.

This is the first time we've measured the σ_eval lower bound on this dataset.

|---|---|---|---|
| I-651 multi-cate | -0.0025 | ~6σ | confirmed KILL |
| I-653 UserPair | -0.0050 | ~12σ | confirmed KILL |

\* Mislabeled, but the LB number is real.

**Operational rule going forward**: future LB results within ±0.0008 of the
fork-base SOTA should be treated as noise unless reproduced across ≥2 seeds.
Real signal threshold ~ ±0.0010 on this dataset.

## Lesson learned

Submission packaging must verify the code diff matches the design before
upload. Add a pre-submission checklist (smoke test) to fork-dir contracts
so design-only experiments cannot be silently shipped as code submissions.
