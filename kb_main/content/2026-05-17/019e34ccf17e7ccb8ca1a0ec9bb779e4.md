# I-653_user_pair

```yaml
id: I-653
name: user_pair
status: ready_for_smoke
base: experiments/I-643_cate_oof_heat/code/
fork_base: "experiments/I-643_cate_oof_heat/code/"
baseline_lb_auc: 0.822863  # I-625
i643_reference_lb: 0.824608

rationale:
  - Fids 62/63/64/65/66 appear in both user_int_feats and user_dense_feats.
  - Existing model projects all user_dense features as one raw vector and all user_int
    features through NS tokenizer embeddings, but it has no explicit low-capacity
    same-fid pair interaction.
  - A- design verifies the mechanism without adding gate/cross-attention capacity.

design:
  fusion: concat(user_int_X embedding, user_dense_X slice) -> Linear -> LayerNorm -> SiLU
  fids_default: [62, 63, 64, 65, 66]
  per_pair_hidden_dim: 16
  output_path: append pair features to raw user_dense vector before user_dense_proj
  ns_token_count_change: 0
  gate: false
  attention_change: false
  tokenizer_embedding_reuse: true
  active_stack: inherits I-643 single cate heat fid 84 only

risk_controls:
  - USER_PAIR_FIDS env controls subset ablation, e.g. USER_PAIR_FIDS=62,63.
  - No new Embedding tables are created; pair fusion reuses user_ns_tokenizer embeddings.
  - If emb_skip_threshold skips a high-card fid, pair fusion receives the same zero vector
    as the NS tokenizer, preserving the OOV/capacity guardrail.
  - Adds only one small projection per requested pair plus the enlarged user_dense_proj.

expected_delta:
  range_vs_i643: [-0.002, 0.002]
  promote_if: "leaderboard_auc >= 0.826"
  neutral: "0.824 <= leaderboard_auc < 0.826"
  kill_if: "leaderboard_auc < 0.824"

challenge_notes:
  - Do not call this fully OOV-safe: fids 64/65/66 are high-card user-like fields in demo EDA.
  - If full 62-66 KILLs, rerun subset 62,63 before closing the UserPair mechanism.
  - Do not escalate to B/C unless A- is directionally positive on LB.

smoke_test:
  - `python -m pytest test_user_pair_fusion.py -q`
```
