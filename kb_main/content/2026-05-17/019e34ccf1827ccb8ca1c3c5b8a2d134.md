## Rationale

### Why now (axis fit)

I-643 holds 0.824608 SOTA and 5 attack experiments (multi-cate stack, UserPair,
dow stack, alpha sweep, chorus funnel) all regressed -0.001 to -0.005. The
feature axis is locally saturated. The training-dynamics axis is being tested
in I-656 (β2=0.99). The **calibration sub-axis** of the loss-family is still
formally open per `feedback_loss_axis_closed.md` 2026-05-06 refinement:

> "Closed applies to reweighting (focal-family) and pairwise (BPR/RankNet/PWiseR)
>  sub-axes only. Calibration-aware ranking head ... still OPEN until tested."

Our 4× CTR drift across the 5-day window (D0=2.84% → D9=11.74%) is
structurally a **calibration drift**, not a ranking failure. BCE optimizes
calibration in expectation but does not have an explicit head correcting
context-conditional bias. MLPlatt adds exactly that.

### Why MLPlatt (mechanism fit)

MLPlatt (arXiv 2601.08345, Jan 2026) is a post-projection calibration head:

- **Context MLP** ingests selected non-item features (paper explicitly excludes
  item features by design) and produces a small calibration context vector.
- **MonoMLP** ingests `[context, raw_logit]` and outputs a calibrated logit,
  with a monotonicity penalty term added to the loss to enforce
  `∂calibrated_logit / ∂raw_logit ≥ 0`.
- Base model is frozen during calibration training in the paper. We adapt
  this to **joint training** with stop-gradient between base BCE and
  calibration BCE so the base model dynamics stay byte-identical to I-643.

### Why pattern A risk is mitigated

I-624 (target-aware token gate) and I-639 (time-feat context gating) both
KILLed -0.0022 / -0.0025. Both injected `target_item_emb` into a context
that conditioned a learnable scaling. The failure mode is item-conditioned
amplification of train-time identity binding.

MLPlatt avoids this by design. Per arXiv 2601.08345 explicit text (DocSpec2
verified): "item features x_item are NOT used as inputs to the calibration
model." Our context input is restricted to:

- `inputs.user_dense_feats` (raw vector, pre-projection) — user-side, not
  item-side.

(The paper also lists position-in-list and time-of-day. Position is not
applicable to our point-wise CVR task. Time-of-day per row is not an
explicit row-level feature in the current ModelInput; deferring as v2
extension after Codex challenge.)

## Design (v2 — post Codex challenge 2026-05-09)

v1's identity init was a confirmed bug (zero-weight MLP zeros raw_logit
before final layer). v2 uses **residual path** (Codex A5 fix option a).

### MLPlatt head module

```
class MLPlattCalibrationHead(nn.Module):
    """Context-aware monotone Platt scaling on logits — residual variant.

    Reference: arXiv 2601.08345 (Jan 2026). Item features intentionally
    excluded from context per paper design.

    Architecture: cal_logit = raw_logit + mono_mlp([context, raw_logit_detached])
    Residual ensures exact identity at any init when mono_mlp branch is zero.
    """
    def __init__(self, user_dense_dim: int, context_dim: int = 8,
                 mono_hidden: int = 8):
        super().__init__()
        self.context_mlp = nn.Sequential(
            nn.Linear(user_dense_dim, 32), nn.SiLU(),
            nn.Linear(32, 16), nn.SiLU(),
            nn.Linear(16, context_dim),
        )
        # MonoMLP outputs a residual delta on top of raw_logit
        self.mono_mlp = nn.Sequential(
            nn.Linear(context_dim + 1, mono_hidden), nn.SiLU(),
            nn.Linear(mono_hidden, mono_hidden), nn.SiLU(),
            nn.Linear(mono_hidden, mono_hidden), nn.SiLU(),
            nn.Linear(mono_hidden, 1),
        )
        # Zero-init the FINAL layer of mono_mlp so the residual branch
        # produces 0 at init → cal_logit = raw_logit exactly.
        # Other layers use default Kaiming/Xavier so the network has
        # non-degenerate signal flow once it starts learning.
        with torch.no_grad():
            last = self.mono_mlp[-1]
            nn.init.zeros_(last.weight)
            nn.init.zeros_(last.bias)

    def forward(self, raw_logit: torch.Tensor,
                user_dense: torch.Tensor) -> torch.Tensor:
        # raw_logit: (B, 1) — single-action CVR logit. **Pre-detached by
        # caller** (trainer) to prevent gradient contamination of base.
        # user_dense: (B, user_dense_dim) — pre-projection raw vector.
        context = self.context_mlp(user_dense)              # (B, context_dim)
        x = torch.cat([context, raw_logit], dim=-1)         # (B, context_dim+1)
        delta = self.mono_mlp(x)                            # (B, 1) zero at init
        cal_logit = raw_logit + delta                       # residual
        return cal_logit
```

**Critical contract**: `raw_logit` passed in MUST be already detached by the
trainer (`raw_logits.detach().requires_grad_(True)` for the calibration
branch). This decouples I-643 base dynamics from the calibration head per
Codex A1 ruling. The base BCE loss continues to drive the original (non-
detached) logits through the standard chain rule; the calibration branch
operates on a separate computational subgraph.

### PCVRHyFormer integration

`model.py` `PCVRHyFormer.__init__` adds optional `mlplatt_head`:

```python
if cfg.get("use_mlplatt", False):
    self.mlplatt_head = MLPlattCalibrationHead(
        user_dense_dim=user_dense_dim,
        context_dim=cfg.get("mlplatt_context_dim", 8),
        mono_hidden=cfg.get("mlplatt_mono_hidden", 8),
        mono_layers=cfg.get("mlplatt_mono_layers", 3),
    )
else:
    self.mlplatt_head = None
```

`forward()` after `logits = self.clsfier(output)`:

```python
if self.mlplatt_head is not None:
    cal_logits, _ = self.mlplatt_head(logits, inputs.user_dense_feats)
    return logits, cal_logits  # tuple — trainer/infer handle both
return logits  # backward-compat single-tensor return
```

`predict()` mirrors `forward()`.

### Loss (joint training, v2)

`trainer.py` `_train_step` after model call:

```python
raw_logits = self.base_model(batch_input)  # base forward unchanged
base_loss = F.binary_cross_entropy_with_logits(raw_logits, label)

if self.mlplatt_head is not None:
    # DETACH raw_logits before calibration branch (Codex A1 fix)
    raw_detached = raw_logits.detach().requires_grad_(True)
    cal_logits = self.mlplatt_head(raw_detached, user_dense_feats)
    cal_loss = F.binary_cross_entropy_with_logits(cal_logits, label)

    if self.mlplatt_alpha_mono > 0:
        # Slope penalty in fp32 explicitly (Codex new attack #3 — AMP
        # autocast can produce noisy fp16 slopes).
        with torch.cuda.amp.autocast(enabled=False):
            cal_logits_fp32 = cal_logits.float()
            raw_detached_fp32 = raw_detached.float()
            slope = torch.autograd.grad(cal_logits_fp32.sum(),
                                        raw_detached_fp32,
                                        create_graph=True,
                                        retain_graph=True)[0]
            mono_penalty = F.relu(-slope).mean()
    else:
        mono_penalty = torch.zeros((), device=raw_logits.device)

    loss = base_loss + self.mlplatt_alpha_cal * cal_loss + self.mlplatt_alpha_mono * mono_penalty
else:
    loss = base_loss
```

Default coefficients (Codex A3 revision):
- `mlplatt_alpha_cal = 0.25` (NOT 1.0 — first question is "can calibration
  help at all", not "let head dominate base")
- `mlplatt_alpha_mono = 0.05` (NOT 0.1 — same rationale; small probe)

Codex demanded separate gradient clip for base vs head — apply
`torch.nn.utils.clip_grad_norm_` separately on the two parameter groups
during `optimizer.step()`.

### Inference (v2 — Codex A4 fix)

**Do NOT blindly use cal_logits for LB submission.** Codex flagged this is
silent failure prone — if MonoMLP learns a bad mapping (e.g. compresses all
logits toward 0), `cal_logits` ranks worse than `raw_logits` and we burn an
LB slot on a regression we could have caught.

Inference protocol:
1. During training: log on validation each epoch:
   - `raw_auc`, `cal_auc`
   - `mean_abs_delta = mean(|cal_logits - raw_logits|)`
   - `pearson(cal_logits, raw_logits)`
   - `rank_flip_rate` (% of pairs whose order changed between raw and cal)
2. At infer time: emit BOTH raw and cal predictions to disk.
3. **Pick `cal_logits` for LB only if** `cal_auc > raw_auc - 0.0003` AND
   `pearson > 0.98` AND `rank_flip < 2%` on the last validation batch.
4. Otherwise emit `raw_logits` (degenerates to I-643 + a wasted training of
   MLPlatt head — no LB regression).

## Risk Audit

- **Pattern A (item-conditioned KILL)**: mitigated by paper design — context
  excludes all item features. Risk class same as I-625 (user-internal).
- **MonoMLP not actually monotone**: relies on penalty, not architectural
  constraint. If penalty alpha too low, MonoMLP could learn non-monotone
  mapping. Mitigation: identity init + alpha_mono=0.1 initial.
- **Joint training shifts I-643 dynamics**: backprop through `cal_loss` flows
  into base model via `raw_logit`. Even with stop-gradient pattern, the
  monotonicity penalty's autograd on `cal_logits.sum()` w.r.t. `raw_logits`
  creates an indirect gradient path. **Critical Codex challenge target**.
  Mitigation candidate: `raw_logit.detach()` before passing to MLPlatt, so
  base model is fully decoupled.
- **Capacity addition**: Context MLP (~5K params) + MonoMLP (~250 params).
  Negligible vs 64-dim PCVRHyFormer total. Not a capacity-axis violation.
- **Cold restart interaction**: MLPlatt head is dense (small MLP), goes
  into AdamW optimizer state, NOT reset by cold restart. Confirmed
  consistent with project S3 prior.

## Stack potential (v2 — Codex A7 correction)

MLPlatt is post-projection on logit. **Orthogonal to** I-625 gap features,
I-643 cate heat, I-606 amp+compile.

**NOT orthogonal to I-656 β2=0.99** (Codex correction): β2 changes the
adaptation speed of dense AdamW, which trains BOTH the base model AND the
MLPlatt head. The two are coupled through optimizer dynamics, not just
through inputs/outputs.

Stacking rule (revised): **do not stack I-656 + I-657 until each promotes
independently on top of pure I-643 base**. If both promote, run I-658
(joint) as a third experiment after seeing the additive structure.

**NEW attack surfaces** (Codex found beyond A1-A7):
1. **Shape/protocol ambiguity** — `forward` returns `(raw, cal)` tuple but
   `predict` returns `((raw, cal), output)` per IMPLEMENTATION_PLAN.md.
   Every call site in trainer/evaluator must be audited. v2 fixes by
   moving residual into the head (single tensor return) but joint loss
   still needs the raw + cal pair, so trainer-side dispatch is unavoidable.
2. **Context leakage via `user_dense_feats`** — must do schema audit
   (added to meta.md "Pre-implementation schema audit" section).
3. **AMP × autograd** — slope penalty in `_amp_autocast()` produces noisy
   fp16 slopes. v2 forces fp32 cast around the autograd.grad call.

**Hard kill conditions added** (post-Codex, beyond v1's 3):
- val `cal_auc < raw_auc - 0.0003` after any epoch
- `pearson(cal_logits, raw_logits) < 0.98` on validation
- rank-flip rate > 2% without AUC gain
- base raw-logit val AUC drops > 0.0005 vs I-643 reproduction
- training wall-clock overhead > 20% after detached-raw implementation
- any item/listing feature found in calibration context

**Shipping order**: I-656 first (per Codex; substantive risk lower).
I-657 implementation only commences after I-656 LB result is in AND
schema audit passes.

### Mechanism reading

MLPlatt was supposed to correct D0→D9 calibration drift. Result tells us
**train-distribution calibration is itself non-transferable** — same root
cause that killed all 4 reweighting/pairwise variants:

- focal/PWiseR/Combined-Pair learn ranking under train distribution → over-fit
- MLPlatt learns calibration under train distribution → also over-fit

The residual structure (cal = raw + delta) and item-free context (Codex A1
pattern A defense) **worked as designed** — pattern A check confirmed by
no NaN, no degenerate behavior. The mechanism just doesn't transfer on
this dataset.

### Conjunction with I-657b confirms

I-657b at α_cal=0.50 dropped LB to **0.817078** = -0.007530 vs I-643.
Direction is **monotonic negative**: more calibration weight → bigger LB drop.
This is mechanism confirmation, not configuration noise. α-sweep further
won't recover.
