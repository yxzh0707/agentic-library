# Algorithm Review Protocol

> 算法方案的多视角评审机制。用于自研架构设计、增强包评估等关键算法决策。
> Claude Code + Codex 共识方案（2026-04-12）。

---

## 流程概览

```
第一轮：独立提案（3 Agent 并行）
     ↓
第二轮：交叉审查（3 Agent 并行）
     ↓
第三轮：Red Team 攻击（1 Agent）
     ↓
第四轮：Judge 收敛（1 Agent）→ 最终方案
```

---

## 第一轮：独立提案

3 个 Agent 并行，互不可见，各自给出完整方案。

| Agent | 约束 | 视角 |
|-------|------|------|
| **AUC 猎手** | 不限复杂度，追求最高精度 | 大模型、深层堆叠、MoE、复杂交互 |
| **延迟猎手** | p95 必须 < 10ms，追求效率 | 轻量 mixing、KV cache、金字塔截断、量化 |
| **创新猎手** | 要能冲创新奖 $45K，追求新颖性 | Scaling law 实验、新型 attention、统一 block 创新 |

每个提案必须包含：
- 架构描述（tokenizer、attention、FFN、norm、output head）
- 预期 AUC 改进（相对于 baseline）
- 推理延迟估算
- 实现复杂度（人天）
- 关键假设和风险

---

## 第二轮：交叉审查

3 个 Agent 并行，每人读另外两个方案，输出：
- 最值得吸收的 1-2 个点
- 最大的技术风险
- 实验成本评估
- 可能的伪增益（在小样本上看起来有效但 scale 后可能失效）

---

## 第三轮：Red Team

1 个 Skeptic Agent，专门攻击所有方案：
- 在 1000 样本上有效但 full data 可能失效的部分
- 数据泄漏风险
- 过拟合假象
- 与 AngelML 平台约束的冲突
- 与已知 domain_hints 的矛盾
- 实现中容易出 bug 的部分

---

## 第四轮：Judge 收敛

1 个 Judge Agent，读所有材料后输出最终方案。

### 评估 Rubric

| 维度 | 权重 | 说明 |
|------|------|------|
| 预期 AUC 收益 | 30% | 基于论文证据和本地实验推断 |
| 实现复杂度 | 20% | 人天估算，考虑自研 vs 改现有代码 |
| 实验成本 | 10% | GPU 时间、数据需求 |
| 过拟合/泄漏风险 | 15% | 小样本假象、时序泄漏、标签泄漏 |
| 任务契合度 | 15% | 与 CVR 预测、延迟约束、单模型约束的匹配 |
| 是否值得先做 ablation | 10% | 能否低成本验证假设 |

### Judge 输出格式

```yaml
main_plan:
  name: "..."
  architecture: "..."
  key_components: [...]
  estimated_auc_gain: "+X.X%"
  estimated_latency: "Xms"

parallel_enhancements:
  - name: "..."
    priority: 1
    estimated_gain: "+X.X%"
    effort: "X days"

experiment_priority:
  1. "..."
  2. "..."
  3. "..."

rollback_path: "如果主方案失败，回退到..."

risks:
  - "..."
  - "..."
```

---

## 何时触发此流程

- 自研架构的核心设计决策
- 新增强包的方案选择（当候选方案 >= 3 个时）
- Round 间的策略转换
- 任何 ASK 级别的架构变更

不需要触发此流程的场景：
- HPO 微调（直接用 Optuna）
- Bug 修复
- 配置调整
- 单个明确的增强（直接做 ablation）

---

## 执行方式

- 第一轮：Claude Code 启动 3 个并行 subagent
- 第二轮：Claude Code 启动 3 个并行 subagent（输入包含其他两个的提案）
- 第三轮：Claude Code 启动 1 个 Codex rescue agent（Red Team 视角）
- 第四轮：Claude Code 自己做 Judge（综合所有输入）

预计耗时：3-5 分钟。

---

## 自动闭环模式（无人值守）

评审协议 → 实现 → 实验 → 迭代，全程无需人工审批。

### 完整循环

```
评审协议（4 轮）→ Judge 输出方案
    ↓
Claude Code 出技术规格 → Codex 实现代码 → Claude Code 审查
    ↓
实验闭环（训练→评估→manifest→知识检查→建议）
    ↓
根据结果自动决策：
  AUC 提升 > 0.3% → ablation（闭环再跑 4 次）
  AUC 持平        → 换方向（触发新一轮评审）
  AUC 下降        → 回滚到上一最佳
    ↓
下一轮循环
```

### 硬约束

- **总轮次上限：10 轮**（含评审 + 实验 + ablation，超过必须停下等人）
- **单轮实验上限：4 次**（1 次主实验 + 3 次 ablation）
- **Circuit breaker**：连续 3 次 AUC 在 0.001 内 → 强制停止
- **每次实验必须记录**：
  - manifest.json：完整实验条目
  - decision_log.md：每轮的决策理由和结果摘要
  - checkpoint：最佳模型权重保存到 artifacts/checkpoints/
  - 训练曲线：每 epoch 的 train_loss / val_loss / val_auc 存在 result.history 中
- **断点保存**：每轮结束后 git commit + push，确保任何时候中断都不丢失进度
- **知识沉淀**：每轮结束检查 domain_hints.md，有新发现立即更新

### 人工介入触发条件

以下情况自动停止等人：
- 达到 10 轮总上限
- Circuit breaker 触发（停滞或重复错误）
- 实验失败 2 次以上
- AUC 超过前最佳 2% 以上（重大突破需人确认方向）
- 模型架构需要根本性重设计（ASK 级别决策）
