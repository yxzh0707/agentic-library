# I-670 — ML-DCN-style Masked Low-Rank Explicit Cross on Stable Attributes

## Hypothesis

Adding an **explicit polynomial cross** module over the project's STABLE ATTRIBUTE features (user_int + item_int + user_dense), restricted to fields that do NOT depend on the learned `user_id` or `item_id` embeddings, will close part of the 0.0045 LB gap to top-50 target 0.829.

Paper backing (verified ≥2025 via WebFetch in `<PROJECT_ROOT>/docs/research/deep_search/20260513-1511_inquiry_post_mcmlcc_pivot/external_research.md`):
- **ML-DCN (Pinterest, arXiv 2602.09194, 2026)** — primary architectural recipe (masked low-rank crossing under fixed FLOPs)
- DCN^2 (AdKDD 2025) — supporting baseline upgrades
- DLF (SIGIR 2025) — residual-aware explicit-implicit fusion
- Field-Aware Transformer (arXiv 2025) — supporting evidence for field-structured priors

### Official rules
A1. "all sparse features are represented as anonymized integer IDs, and dense features are provided as fixed-length float vectors. No raw content (e.g., text, image, URL) or personally identifiable information is released."

### Failure modes (THIS DESIGN MUST AVOID)
F1. Only "feature-axis (new information) and regularization-axis (less train-overfit) can transfer."
F2. "Any learned id-dependent representation (user OR item) fails to transfer." → **the cross module MUST NOT operate on `user_id` or `item_id` learned embeddings**. Only on the per-fid integer attribute embeddings AND the dense features.
F3. Loss-axis improvements over BCE don't transfer. → keep BCE loss unchanged.
F4. Valid AUC delta < 0.001 has zero predictive power for LB direction. → don't stop on valid; only LB matters.

### Closed-axis traps to NOT recreate
- Multi-cate stack (I-651): don't add MORE cate-OOF-like features
- Gating: ML-DCN's "masked" component is borderline — the mask MUST be a static field-selector / sparsity-inducer, NOT a multiplicative gate on token activations (would recreate I-624/I-639/I-661)
- In-d_model architecture: the cross module is added as a SEPARATE BRANCH that concatenates into the final pre-classifier dense, NOT injected into PCVRHyFormer's d_model attention path (where MC-MLCC just failed)

## Architecture spec

### Module: `MLDCNStableCross`

Inputs:
- `user_int_embed`: per-fid embedding lookups for all 46 `user_int_feats_*` fids → list of 46 vectors, each `d_emb`-dim, concatenated/stacked
- `item_int_embed`: same for 14 `item_int_feats_*` fids → 14 vectors of `d_emb`
- `user_dense`: 736-dim dense vector (from existing `user_dense_feats_*` projection)
- **EXCLUDED**: `user_id` embedding (per F2), `item_id` embedding (per F2)

Output: a single dense vector of dim `d_cross` (suggest `d_cross = 64`)

### Forward steps

1. **Flatten + project to common dim**:
   - Stack all attribute embeddings to a matrix `X ∈ ℝ^{N × d_emb}` where `N = 46 + 14 = 60` (fids), plus optionally concat the dense vector as one or more pseudo-rows
   - Field-aware: each fid keeps its own learnable embedding, no sharing

2. **Low-rank cross** (ML-DCN-style):
   - For each cross step, compute `X' = X + (X @ W_down) @ W_up * mask`
   - `W_down ∈ ℝ^{d_emb × r}`, `W_up ∈ ℝ^{r × d_emb}` — `r = 16` (low rank to control FLOPs)
   - `mask ∈ ℝ^{N × 1}` — **static field-selector** mask (NOT learnable per-instance gate); can be learnable but applied identically to all instances. Initialize to all-ones for safety.
   - Repeat for `K = 2` cross layers (depth-2 sweet spot from ML-DCN)
   - Implementation MUST be vectorized: `bnd, dr -> bnr`, `bnr, rd -> bnd`

3. **Pool to vector**:
   - Sum-pool across the 60 fid axis → vector of dim `d_emb`
   - Concat with `user_dense` projected to `d_emb` → 2*d_emb dim
   - Final linear to `d_cross = 64`

### Integration with I-643

In `model.py`'s `PCVRHyFormer.forward()`:
```python
# Existing I-643 path computes `output` from output_proj
output = self.output_proj(all_q.view(B, -1))   # (B, 64)

# NEW for I-670: add ML-DCN cross branch
cross_out = self.ml_dcn_stable_cross(
    user_int_token_embs,  # already computed for the NS tokens
    item_int_token_embs,
    batch.user_dense,
)  # (B, 64)

# Concat both 64-dim and project to original 64
fused = torch.cat([output, cross_out], dim=-1)  # (B, 128)
output = self.fusion_proj(fused)                # (B, 64)

logits = self.clsfier(output)
```

Add a learnable scalar `gamma_cross` initialized to **0.0** (zero-init residual) — so the model behaves IDENTICALLY to I-643 at step 0; then gradient drives the cross branch in if it helps. This is the same gamma=0 trick from MC-MLCC, applied to a structurally different module.

```python
output = self.fusion_proj(torch.cat([output, self.gamma_cross * cross_out], dim=-1))
```
