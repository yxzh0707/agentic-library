## Mechanism reading

We added an Embedding(65, 16) + Linear(16, d_model) layer that injects
a K-Means cluster code (over 4 OOV-safe cate fids 84/13/81/9) additively
into item_dense_tok. Doc-spec rationale was OOV-safe by construction:
clusters formed on cate fids, new items get nearest centroid.

Why it died harder than expected:
1. I-643 base already absorbs cate-OOF heat statistics via item_dense_proj.
   COINS cluster code is a discretized version of the SAME cate joint
   distribution -> redundant signal AND coarser than the continuous heat
   features I-643 already uses.
2. Adding a sparse Embedding table re-enters the cold-restart regime: 
   reinit_sparse_after_epoch=1 wipes the COINS embedding every epoch,
   so the model has 1 epoch to learn cluster->logit mapping, vs the
   continuous heat path which has the persistent dense projection
   weights doing the same job.
3. The doc-spec QuaSID/SID-Coord +0.42% AUC numbers were on industrial
   bases WITHOUT cate-OOF heat. Once you have the continuous version of
   the same signal, the discretized version is pure capacity-loss.
