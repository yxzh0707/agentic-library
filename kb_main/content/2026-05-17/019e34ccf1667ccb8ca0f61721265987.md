## Rationale

EDA in `docs/eda_pre_wave2.md` section 4 shows `item_id` is a meta column not consumed by baseline, while demo_1000 MI(label) is `0.33606`, the strongest single field and higher than `item_int_feats_16` at `0.28090`.

The 2025 TACC first-place notes emphasized semantic item IDs via RQ-KMeans plus multimodal embeddings. I-608 is a cheaper first probe: hash raw `item_id` into a fixed 2^20 bucket space and feed it through the existing item_int tokenizer path.

Forum evidence says item-side features have worked for competitors around the 0.82 band, so a direct item identity token is worth testing before more expensive semantic ID work.

## Implementation

- Injects a virtual item_int fid `999` inside `dataset.py`; `data/schema.json` is not modified.
- Hashes positive `item_id` values to `[1, item_id_hash_buckets]`; `0` remains padding/missing.
- Adds CLI flags `--use_item_id_token` / `--no_use_item_id_token` and `--item_id_hash_buckets`.
- Sets `run.sh` to `--item_id_hash_buckets 1048576 --emb_skip_threshold 1048576`, because baseline's `1000000` threshold would skip a 2^20-vocab embedding.
- Cold restart should include the new embedding automatically because its vocab is `1048576 > reinit_cardinality_threshold`.
- Fork base is I-606, so `run.sh` preserves `--use_amp --use_compile`.

## Outcome — KILL ❌ (val_auc was misleading; high-card sparse token doesn't transfer)

```yaml
  validates_priors:

    - "test set item D9 vs D0 overlap = 1.8% (data_split_finding) — new train item embeddings don't transfer"
    - "Domain prior S2: in-distribution val (rowgroup split) does NOT predict leaderboard"
```

**Reading**: I-608's record val_auc 0.8637 was train memorization, not generalization.
With cold restart resetting the 67M item_id_hash embedding every epoch, the model
re-learned train item_ids each epoch but **could not transfer to test set** where
item_ids are mostly disjoint (1.8% overlap per data_split_finding).

Net effect of item_id_hash on baseline-0: **-0.00030 leaderboard** (essentially
identical to I-606 amp+compile alone). The 67M new sparse parameters added zero
leaderboard signal.

**Strategic implication**: New high-cardinality sparse embeddings on TencentGR are a
trap. Future experiments adding sparse capacity must show reasons why their feature
would transfer across train/test ID disjoint set. Dense projections (cf. I-605) are
the safer feature engineering path.
