# Algorithm Review Round 1 — 自研 UniRec 核心架构

Date: 2026-04-12
Trigger: Day 4 自研架构核心设计决策

## 第一轮：独立提案

### 方案 A（AUC 猎手）— UniRec Pro
3-stage encoder：domain-private causal(2层x4) → target-aware cross-attention + MoT → unified cross block(2层)。Per-token FFN + GLN + SEP + NAL + 动态 Masking + BlockAttnRes。8-12M 参数，预期 15ms，预期 AUC +1.5-3%。实现 3 人天。

### 方案 B（延迟猎手）— UniRec-Lite
7 tokens（全部 mean pool），2 层 MixerBlock。HeadMixing + Per-token FFN + GLN。延迟 1.6ms，预期 AUC 0.72-0.74。实现 2 人天。

### 方案 C（创新猎手）— FMT
Domain-Factorized Pointwise Attention + Factorized Multiplicative Mixing + Adaptive Token Compression + NAL。预期 AUC 0.77-0.79。Scaling law 实验设计。实现 2-3 天。

## 第二轮：交叉审查共识
- A 组件堆叠过多难归因，延迟估算乐观，3人天偏乐观
- B mean pool 是致命短板，AUC 天花板太低
- C 三个新模块同时引入太激进，数值稳定性风险

## 第三轮：Red Team 结论
- 以 B 为骨架保延迟
- 加 C 的轻量 token compression
- 只保留 A 的 target-aware pooling
- 原则：单塔、2-3 层、少新模块、先保时序再保稳定

## 第四轮：Judge 最终方案 — UniRec-Hybrid

骨架来自 B，序列处理来自 A 的 target-aware pooling，整体保持 2-3 层轻量级。

核心组件：
1. Unified Tokenizer：user/item embed+pool 为 token，4 domain 保留时序
2. 序列：4 domain 各取最近 128 步，learned weighted pool + target-aware attention
3. GLN 三组归一化
4. 2 层 MixerBlock（HeadMixing + Per-token FFN）
5. concat → MLP → logit

预期 AUC：+2-4% vs MLP baseline
预期延迟：3-5ms

增强项：NAL 辅助损失（P1）、动态 Masking（P2）
回滚路径：退到纯 UniRec-Lite
