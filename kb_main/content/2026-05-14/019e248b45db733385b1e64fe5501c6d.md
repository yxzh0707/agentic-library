# 2025 TACC 夺冠思路速览 + 我们能借什么

> **目的**：用大白话把 2025 年 TACC（同一赛道的去年版本）4 支获奖队伍的核心创新讲清楚，
> 标注**我们已经做的 / 可以借的 / 暂时不做的**，最后给一份"未来 30 天该往哪挖"的优先级图。
>
> **读这份的姿势**：你不需要 ML 背景，每节都有"大白话比喻"。看完你应该能回答：
> "我们离冠军方案还差几条路？哪条最值得花配额去打？"

---

## TL;DR：一张总图看清楚我们在哪

去年 4 支获奖队伍各自押注了**不同的轴**。我们目前只在**时间特征**这一格上有产出（I-605 +0.006），其他格子大部分还没动。

| 创新轴 | 🥇 第一 | 🥈 第二 | 🥉 第三 | 🏆 技术创新 | **我们的状态** |
|---|:---:|:---:|:---:|:---:|---|
| 时间特征工程 | 三级 + 多频 Fourier | — | 绝对+gap | 多窗口热度统计 | ✅ I-605 已做一半，I-625 在跑 |
| 行为条件化（Action Conditioning） | FiLM+Gated+AttnBias | Decoder 注入 | 输入注入 | 联合预测 | ❌ 完全没做（schema 待确认） |
| 语义 ID（RQ-KMeans 等） | ✓ | ✓+SVD | — | ✓+碰撞解决 | ❌ 没有多模态 emb，做不了 |
| 模型容量扩展 | 标准 | **2048d/8 层（×4096）** | Scaling Law 研究 | MoE | ⚠️ I-604 试过深度+1 失败 |
| Scaling Law（负样本/规模） | Large Negative Banks | — | **核心研究** | — | ❌ 我们是 BCE，没用 InfoNCE |
| 工程优化（AMP/Compile） | 静态图 | — | AMP+Compile | FlashAttn+KV Cache | ✅ I-606 已做 AMP+Compile |
| 训练策略 | Muon+AdamW | 两阶段（pretrain→finetune）| AMP | 分组 Optimizer | ⚠️ 默认 AdamW 单阶段 |
| 推理后处理 | ANN 检索 | 过滤历史交互 | — | KV Cache | — |

**一句话**：我们在 8 条轴上**只占了 1.5 条**（时间特征 1 条 + 工程优化半条）。冠军方案是把多条轴叠加起来才达到那个分数的——我们仍有大量未挖的方向。

## 🥇 第一名：行为条件化 + 三级时序 + 语义 ID + Muon

**一句话定位**：「不同的行为信号，不能一锅烩——给每条历史行为打上"曝光/点击/转化"标签，让 Transformer 区别对待」

### 核心创新（5 个组合拳）

#### 1. Per-position Action Conditioning（最核心）
**问题**：用户的历史行为里 94% 是"曝光"（看了一眼但没动作），只有 2.85% 点击、2.52% 转化。把它们当一样的 token 喂进 Transformer，**强信号会被弱信号淹没**。

**解法**：每个位置根据"这是哪种行为"去**改造它的表征**：
- **FiLM**（仿射变换）：把 token 表示 `x` 变成 `γ × x + β`，γ 和 β 由"行为类型"决定。比喻：**把同一段话用不同语气重读一遍**——"被点击"语气强调，"被曝光"语气低调
- **Gated Fusion**（门控融合）：用一个开关决定"用原始版本还是变形版本"，强信号靠变形，弱信号保留原始
- **Attention Biasing**（注意力偏置）：让 Transformer 在算"哪些历史更重要"时，**主动给点击/转化位置加权重**

> **大白话比喻**：开会做笔记时，老板和实习生都说话了。FiLM 让你给每个人的话**自动加一个"重要性滤镜"**，Gated Fusion 让你决定"老板的话原话记 vs 老板的话浓缩重写"，Attention Bias 让你**优先抄老板的话**。

#### 2. 三级时序特征工程
- **Level 1**：小时 / 星期几 / 节假日（绝对时间特征）
- **Level 2**：相邻事件间隔（Inter-event Gap）← **I-625 在做的**
- **Level 3**：Session 结构（同一次访问 / 跨天回访）
- 加上**多频 Fourier 编码** ← **I-605 在用的**

#### 3. RQ-KMeans 语义 ID
把广告的多模态 embedding（文本+图像）层层量化成树状码字。语义相近的广告**前缀相同**——长尾新广告也能受益。**前提：要有多模态 embedding**，我们的脱敏数据没有，先放下。

#### 4. Muon + AdamW 混合 Optimizer
新优化器（2024 年），稠密层用 Muon、稀疏 embedding 用 AdamW。号称比纯 AdamW 收敛快、效果好。

#### 5. Large Negative Banks（InfoNCE 大负样本库）
跨 batch 维护负样本池，每步抽几十万个负样本算 InfoNCE 损失。**前提**：损失函数要是 InfoNCE，我们现在是 BCE，要换。

### 对我们的启发
| 创新 | 我们能借吗 | 优先级 |
|---|---|---|
| Action Conditioning（FiLM/Gated/AttnBias）| 🟢 能借——但要先确认数据 schema 里有"行为类型"字段（exposure/click/conversion）| **P0** |
| 三级时序 | ✅ 已部分借（I-605/I-625），剩 Level 1+3 | **P1** |
| RQ-KMeans 语义 ID | 🔴 借不了——没多模态数据 | — |
| Muon optimizer | 🟡 风险中等——换优化器很容易破坏已有 +0.006 | **P3** |
| Large Negative Banks | 🟡 需先把 BCE 换 InfoNCE，改动大 | **P3** |

## 🥈 第二名：Encoder-Decoder + GNN + 大容量 Transformer

**一句话定位**：「干脆把模型做大 4096 倍，再用图神经网络补一刀协同信号」

### 核心创新

#### 1. 模型容量直接拉爆
Baseline 是 1 层、32 维。第二名直接干到 **8 层、2048 维**——容量约 4096 倍。这是他们涨点的最大单一来源。

> **大白话**：别 fancy 别花活，**把脑子做大就能记更多东西**。

#### 2. GNN 图邻居增强
在"用户-物品"二部图上采样邻居，把"和你类似的用户喜欢的广告"也聚合进来。**优势**：补充了 Transformer 抓不到的高阶协同信号；**劣势**：实现非常复杂。

#### 3. 两阶段训练（Pretrain → Finetune）
- 阶段 1：在**全量曝光数据**（弱信号、量大）上预训练，学个基础表征
- 阶段 2：在**点击+转化数据**（强信号、量小）上微调，校准到目标

> **大白话**：先看 100 万张普通照片练眼力，再用 1000 张高质量样片精修。类似 LLM 的 Pretrain → SFT。

#### 4. 推理后处理：过滤历史交互
ANN 检索出 Top-K 后，**移除用户已经买过的广告**，提高新颖性。

### 对我们的启发
| 创新 | 我们能借吗 | 优先级 |
|---|---|---|
| 模型容量扩展（宽度方向）| ⚠️ I-604 加深 1 层失败了，但**维度（d_model 64→128）还没试** | **P2** |
| GNN 图增强 | 🔴 改动巨大，回报不确定 | — |
| 两阶段训练 | 🟢 可借——如果数据里能区分曝光/点击/转化 | **P1** |
| 过滤历史交互 | 🟢 工程上很简单，但我们是 ranking 任务，未必需要 | **P3** |

## 🥉 第三名：生成推荐的 Scaling Law 研究

**一句话定位**：「与其设计花架子，不如把'规模'拉满——这是论文级的系统研究」

### 核心创新（一个核心洞察）

> **规模（Scale）> 复杂模型设计**

他们系统测了三个维度的 Scaling：

| 维度 | 关键发现 |
|---|---|
| **负样本数量**（最关键）| 从 1 → 38 万，性能**还在涨**没饱和 |
| **模型容量**（深度×宽度）| 遵循幂律，越大越好 |
| **Item ID Embedding 维度** | 同等计算量下，**比加深 Transformer 层数更高效** |

### 工程加速
- AMP 混合精度（FP16/BF16 前向 + FP32 更新）
- `torch.compile` 静态图编译

### 对我们的启发
| 创新 | 我们能借吗 | 优先级 |
|---|---|---|
| **Scaling Law 思路本身** | 🟢 启示极强——下次没思路时优先扩规模而不是叠模块 | **P0**（思维方式）|
| AMP + torch.compile | ✅ I-606 已做（+1.87× 速度，-0.003 AUC，可接受）| 完成 |
| 大负样本数 | 🟡 需先把 BCE 换 InfoNCE | **P3** |
| Item ID Embedding 维度扩展 | 🟢 实现简单，可单独打 | **P2** |

## 🏆 技术创新奖：统一检索+排序 + MoE + 多窗口热度

**一句话定位**：「一个模型干两件事（找广告 + 预测行为），加 MoE 让参数量爆炸但计算量可控」

### 核心创新

#### 1. 统一检索 + 排序
传统是"粗排找候选 → 精排打分"两个独立模型。他们用**一个 Decoder 同时学两个任务**：
- 任务 A：生成下一个用户感兴趣的物品（检索）
- 任务 B：预测对它的行为类型（排序）

#### 2. DeepSeek-V3 风格 MoE
每个 FFN 层换成 N 个专家，每次只激活 Top-K 个。**总参数量 ×N，但每个样本计算量不变**。

> **大白话**：模型从一个全科医生变成一群专科医生组成的医院，每个病人只挂 1-2 个最对症的专家号。

#### 3. **多时间窗口物品热度统计**（很值得借）
为每个广告统计**过去 1h / 6h / 1d / 7d / 30d** 的曝光/点击/转化次数，作为**显式特征**喂给模型。
- 短窗口（1h）→ 实时爆发力
- 长窗口（30d）→ 稳定品质
- 弥补"纯序列模型缺乏全局物品信号"的盲区

#### 4. 协同 Embedding + 碰撞解决（语义 ID 改进）
跳过——依赖多模态数据。

### 对我们的启发
| 创新 | 我们能借吗 | 优先级 |
|---|---|---|
| 统一检索+排序 | 🔴 范式改变，巨改 | — |
| MoE | 🔴 改动巨大 | — |
| **多时间窗口热度统计** | 🟢 **可直接搬！** 算一下"广告过去 N 小时被点击次数"塞特征里 | **P1** |
| FlashAttention / RMSNorm / SwiGLU | 🟡 模块替换，I-606 base 暂用默认 attention，等容量上来再考虑 | **P3** |
| RoPE | 🟢 train.py 里已实现没启用，可一行打开 | **P2** |
| KV Cache | 🟢 推理时优化，对延迟有帮助 | **P2**（Round 1 提交前必做）|

## 一个反思

我们目前**在时间特征这条路上的成功容易让人产生"路径锁定"**：以为"再加点时间特征就能继续涨"。但看完冠军全图，**时间特征只是 8 条轴里的 1 条**。下一阶段更大概率的涨点来自：
1. 行为条件化（最大未开发金矿）
2. 多窗口热度统计（实现简单、信号正交）
3. Scaling Law 思路下的容量扩展（不是加层数，是加宽度/embedding 维度）

**Round 1 截止前，时间特征轴最多再值 +0.005~0.010；要再上一个台阶（0.83+），必须开新轴。**
