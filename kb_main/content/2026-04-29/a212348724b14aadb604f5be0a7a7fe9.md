# MTGR — 美团把 HSTU 工业化、保留 cross feature

> arxiv 2505.18654 | Meituan | CIKM 2025

## 它解决了一个赛题相关的痛点

HSTU 这类生成式架构有个工程问题：**抛弃了传统 DLRM 的 cross feature**（特征交叉显式建模），导致工业线上效果反而下降。MTGR 想把两者融合：HSTU 的 scaling + DLRM 的 cross feature 显式建模。

这跟赛题的 framing 完全一致——**统一 backbone 不能简单丢掉传统特征交叉的语义**。

## 两个关键技术

### Group-Layer Normalization (GLN)
不同语义空间（user / candidate / cross）的 token 用不同 LayerNorm 参数。这避免了把语义异构的 token 强行归一化到同一分布。

赛题映射：parquet 列前缀（user_int / user_dense / item_int / 各 domain 序列）天然给了语义分组，每组一套 LN 参数几乎是免费的，但效果可能很显著。

### Dynamic Masking
避免训练时未来信息泄漏。HSTU 的 causal mask 在多 token 类型混合时容易出错（比如 candidate token 不该被 sequence token attend），MTGR 给出动态 mask 规则。

## 工业数字
- 与 DLRM baseline 比：单样本前向 **65x FLOPs**（参数显著增加）
- 训练成本：不变
- **推理成本：-12%**（注意，是降低！原因是 HSTU 的稀疏化和单 backbone 省掉了 DLRM 多塔传递）
- 美团外卖主流量已部署

## 赛题里直接能用的两个 trick

1. **Group-Layer Normalization**：几乎零成本的精度提升候选，第一时间应该上
2. **Dynamic Masking**：处理 [Sequence_A, Sequence_B, Sequence_C, Sequence_D, User_Tokens, Item_Tokens, Cross_Tokens, Candidate_Token] 这类多类型 token 混合时必须有

## 跟 OneTrans 的关系

MTGR 用了 HSTU 的 spatial aggregation；OneTrans 用了 standard MHA。两者在 token 化层面思路接近，但 OneTrans 把"参数共享/独占"做得更细。

可以这么排序：
- HSTU: 同一类 spatial aggregation 应用于所有 token，无 NS 区分
- MTGR: HSTU + 按语义分组的 LN，**有 NS 区分但只在 norm 层**
- OneTrans: 标准 MHA + 按语义分组的整套 W，**NS 区分到每个 attention 矩阵**

赛题选型：MTGR 是 HSTU 上的最小改动，OneTrans 是更深的改动。先 MTGR 看上限，必要时再 OneTrans。
