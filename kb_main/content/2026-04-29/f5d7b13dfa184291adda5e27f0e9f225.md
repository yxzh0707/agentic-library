# 赛题背景与任务

## 背景

推荐系统支撑着内容平台（信息流、短视频）和数字广告（CTR/CVR 预测），每日做出数十亿次实时决策。

过去二十年的推荐研究沿两条主线发展：

1. **特征交互模型** — 建模高维多字段类别/上下文特征
   - Wide & Deep, FM, FFM, DCN, xDeepFM, AutoInt 等

2. **序列模型** — 通过嵌入检索和 Transformer 捕捉用户行为时序动态
   - DIN, DIEN, SASRec, BERT4Rec, HSTU 等

**问题**：两条路线独立演进，造成工业系统的结构瓶颈：
- 跨范式交互浅层
- 优化目标不一致
- 可扩展性受限
- 工程复杂度高

## 赛题要求

> 统一两个传统独立分支：序列行为建模 + 非序列多字段特征交互

参赛者需构建一个**单一的、同构的主干网络**，使用**可堆叠的统一 block** 处理两类特征并建模其关联。

## 数据构成

| 类型 | 说明 |
|------|------|
| 序列行为数据 | 用户历史交互 (item_id, action_type, timestamp) |
| 用户特征 | 匿名化整数字典特征 |
| 广告特征 | 匿名化整数字典特征 |
| 上下文特征 | 稀疏特征 (int) |
| 交叉特征 | 稠密嵌入 (float_array) |

## 评估指标

- **ROC-AUC**（越高越好）
- 延迟约束（超时视为无效）
- 禁止 ensembling

## 创新奖项

1. **Unified Block Innovation Award** — 统一架构创新
2. **Scaling Law Innovation Award** — 缩放定律探索

> 均独立于排行榜，论文评审更注重创新性和洞察力
