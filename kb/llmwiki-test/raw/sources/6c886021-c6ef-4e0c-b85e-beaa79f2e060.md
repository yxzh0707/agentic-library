# 综合作战计划 v2（吸收第二轮深度搜索后的修订）

> 此节点替代 11 号节点的 v1 计划，加入 Kunlun/MFU/FAT/Sample Is Feature/Muon/RoPE/ESMM/蒸馏 等。

## 三档实验路线（按代价递增）

### Tier 1 — 必做（最小可行，1-2 周）
**目标**：在赛题数据上跑通一个能交的 baseline，建立提交流水线

1. 跑 baseline (DeepContextNet, suyanli220) 一遍，记录 AUC + 单样本延迟
2. 加 **Group-Layer Normalization** (MTGR)：几乎零代价 +0.1~0.3% AUC
3. 加 **多任务 head** (ESMM 风：CTR head + CVR head 共享 backbone)：+0.3~1.0% AUC
4. 加 **Next Action Loss** 辅助 (TransAct V2)：+0.1~0.3% AUC
5. NS 侧 token 数从 baseline 的 2 个扩到 group-wise 8-16 个 (OneTrans Group-wise tokenizer)：+0.3% AUC

**提交节点**：Tier 1 完结时已有 +1~2% AUC vs baseline，并在延迟内

### Tier 2 — 拼 leaderboard（2-4 周）
**目标**：把单模型推到 leaderboard 前列

1. 把 backbone 从 baseline HSTU 换成 **MTGR-style HSTU + GLN + dynamic mask**
2. NS token 用 **OneTrans 的 token-specific 参数**（S 共享 + NS 独占）
3. 训练阶段开 **大 OneTrans-L teacher，蒸馏到 MTGR-S student**（合法路径）
4. **timestamp-aware RoPE**（替换 baseline 的对数时间分桶 + 标准 Rotary）
5. 引入 **cross-request KV cache**（OneTrans）— 不影响离线 AUC，纯延迟收益，破排名平局必备
6. **Muon optimizer** for backbone, AdamW for embedding（混合）— 训练 2x 效率，扫超参更多

**提交节点**：Tier 2 配合 Tier 1，预期 +2~4% AUC vs baseline

### Tier 3 — 论文奖（持续投入）
**目标**：拿 Unified Block Innovation Award 或 Scaling Law Innovation Award

#### 路径 A — Unified Block 创新
**论文方向**：在 MTGR 上把 OneTrans 的参数分化 + HyFormer 的 Query Decoding 作为层间池化算子组合，提出新 block

具体做法：
- 偶数层：标准 unified self-attention (OneTrans-style)
- 奇数层：Query Decoding 风 cross-attention（NS query → S 长序列）
- 引入 **field-aware attention** (FAT) 在 NS 内部
- 写论文时用 FAT 的 Rademacher 复杂度框架做理论解释

#### 路径 B — Scaling Law 创新
**论文方向**：在赛题数据上证明 NS token 数量 T 是独立的 scaling 维度

具体做法：
- 跑五档模型（W: 64/128/256/512/1024）× 三档 NS token 数（4/16/64）
- 画 (FLOPs, AUC) 双对数曲线
- 跟 HSTU、OneTrans、Wukong 的 published curve 对比
- 引入 **MFU 度量**（Kunlun）作为效率维度
- 论文落点：W、D、T 三维 scaling law 在赛题数据上的形式

## Token 化层（综合 OneTrans + Sample Is Feature 的折中）

```
[CLS]
[Domain_Type_A | Sequence_A_Events]
[Domain_Type_B | Sequence_B_Events]
[Domain_Type_C | Sequence_C_Events]
[Domain_Type_D | Sequence_D_Events]
[User_Group_1] ... [User_Group_K]   (group-wise NS, K=4-8)
[Item_Group_1] ... [Item_Group_M]   (group-wise NS, M=2-4)
[Cross_Feat_Token]                   (单 token 编码 10 个 user_dense_feats)
[Candidate_Ad_Token]                 (出口预测)
```

序列侧：4 域 timestamp-aware interleave，每事件 = item_id_emb + action_type_emb + time_bucket_emb（拼接而非加法）+ domain_type_emb

非序列侧：group-wise，每个 group 一个 NS token，token-specific 参数

最终预测：用 candidate token 的 hidden 通过一个 head 输出 pCVR，**不**用 CLS

## 训练目标
```
loss = 0.7 * BCE(pCVR_pred, y_cvr)
     + 0.2 * BCE(pCTR_pred, y_ctr)            # ESMM-style multi-task
     + 0.05 * NextActionLoss(seq)              # TransAct V2 自监督
     + 0.05 * KL(student, teacher)             # 蒸馏（Tier 2+）
```

## 工程预算估算
- Tier 1 单模型训练：1 ~ 4 GPU 天
- Tier 2 加蒸馏：3 ~ 10 GPU 天（teacher + student）
- Tier 3 scaling 曲线：每档模型独立训，总 30 ~ 60 GPU 天

## 不确定项（开工后立刻验证）
1. 序列实际长度分布（决定要不要 GSU 风检索）
2. 延迟预算具体数值（决定模型大小上限）
3. label_type 字段编码的语义（决定 ESMM 怎么套）
4. 4 个 domain 的事件数比例（决定 type embedding 维度）
5. user_dense_feats（10 列 cross feature）数值范围（决定 normalize 策略）

## 论文奖项的两条 framing
- **Unified Block 奖**：组合贡献 — MTGR 的 GLN + OneTrans 的参数分化 + HyFormer 的层间交错 + FAT 的 field-aware attention，作为一个新 block。论文叙述围绕"为什么这四个组合是必要的"。
- **Scaling Law 奖**：在赛题数据上画三维 scaling 曲线（W × D × T），用 FAT 的 Rademacher 框架解释为什么斜率正，用 Kunlun 的 MFU 框架解释为什么效率高。论文叙述围绕"赛题数据这个 setting 上 scaling law 的 specific form"。

两个方向都不要追求"全新"，而是"在赛题 setting 上首次验证 + 解释"。这是评审给"洞察力"分的语言。
