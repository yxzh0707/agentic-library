# TAAC2026 赛题全览（问题导向版）

> 来源：[algo.qq.com](https://algo.qq.com/) + [HuggingFace 数据集](https://huggingface.co/datasets/TAAC2026/data_sample_1000) + competition_original.md

---

## 一、核心任务

**统一序列建模与特征交互**（Unified Sequential & Feature Interaction Modeling）

在**单一同构主干网络**中，用**可堆叠的统一 block**，同时处理：
- 多域用户行为序列（序列 token）
- 非序列多字段特征（非序列 token）

输出目标广告的预测转化率 **pCVR**。

> 禁止传统的"序列模型 + 特征交叉模型"双轨并行架构

---

## 二、为什么难

两条独立演进的路线长期分离：

| 分支 | 代表模型 |
|------|---------|
| 特征交互模型 | Wide&Deep, FM, DCN, xDeepFM, AutoInt, Wukong, HiFormer, HyFormer, OneTrans, InterFormer |
| 序列行为模型 | DIN, DIEN, SIM, TWIN, SASRec, BERT4Rec, HSTU, TransAct |

分离导致的结构瓶颈：跨范式交互浅层 / 优化目标不一致 / 可扩展性受限 / 工程复杂度高

---

## 三、评测标准与约束

| 项目 | 说明 |
|------|------|
| **主指标** | ROC-AUC（越高越好） |
| **损失函数** | 交叉熵 |
| **硬性约束** | 推理延迟必须满足限额，超时提交**直接作废** |
| **禁止操作** | 模型集成（Ensemble） |
| **额外奖项** | Unified Block 创新 / Scaling Law 创新（独立于排行榜，论文评审） |

AUC ≤ 0.50 的提交不上榜。同分时按延迟升序打破平局。

---

## 四、数据结构总览

每条训练/测试样本对应一个 **(用户, 上下文, 目标广告)** 三元组，包含：

```
每条样本
├── 序列行为数据     用户历史交互事件（item_id + action_type + timestamp），多个域
└── 非序列多字段特征
    ├── User Features     用户属性（匿名整数）
    ├── Ads Features      广告特征（匿名整数）
    ├── Context Features  上下文稀疏特征（匿名整数）
    └── Cross Features    交叉稠密嵌入（float vector）
```

---

## 五、两种数据格式对比

### 官方原始格式（JSON 嵌套）

**序列数据** — 单一 `seq` 数组，事件对象内联：
```json
{
  "user_id": "1",
  "seq": [
    {"item_id": 16612, "action_type": 1, "timestamp": 1770564000},
    {"item_id": 49638, "action_type": 1, "timestamp": 1770564000}
  ]
}
```

**非序列特征** — 每个特征是数组中的独立对象：
```json
// User / Item / Context Features（整数）
[
  {"feature_id": 8,  "feature_value_type": "int_value",  "int_value": 1},
  {"feature_id": 10, "feature_value_type": "int_array",  "int_array": [1]}
]

// Cross Features（稠密向量）
[
  {"feature_id": 25, "feature_value_type": "float_array",
   "float_array": [0.111, 0.057, 0.121, 0.043, -0.066]}
]
```

---

### HuggingFace 样本格式（Parquet 扁平列）

`demo_1000.parquet`，共 **120 列**，每列直接可访问：

**ID & Label（5列，无空值）**

| 列名 | 类型 | 说明 |
|------|------|------|
| `user_id` | int64 | 用户 ID |
| `item_id` | int64 | 广告物品 ID |
| `label_type` | int32 | 标签（目标变量） |
| `label_time` | int64 | 标签时间戳 |
| `timestamp` | int64 | 请求时间戳 |

**非序列特征（70列）**

| 列名模式 | 列数 | 类型 | 对应原始格式 |
|----------|------|------|-------------|
| `user_int_feats_{fid}` | 46 | `int64` / `list<int64>` | User Features |
| `user_dense_feats_{fid}` | 10 | `list<float>` | Cross Features |
| `item_int_feats_{fid}` | 14 | `int64` / `list<int64>` | Ads Features |

> `{fid}` 即原始格式中的 `feature_id`，编码进了列名

**行为序列特征（45列）**

原始单一 `seq` 按**4个行为域**拆分，`item_id` / `action_type` / `timestamp` 分列存储：

| 域 | 列 | 列数 |
|----|----|------|
| Domain A | `domain_a_seq_38` ~ `domain_a_seq_46` | 9 |
| Domain B | `domain_b_seq_67` ~ `domain_b_seq_79`, `domain_b_seq_88` | 14 |
| Domain C | `domain_c_seq_27` ~ `domain_c_seq_37`, `domain_c_seq_47` | 12 |
| Domain D | `domain_d_seq_17` ~ `domain_d_seq_26` | 10 |

每列类型均为 `list<int64>`，可能含 `null`（缺失序列）。

---

### 格式差异对照

| 维度 | 官方 JSON | HuggingFace Parquet |
|------|-----------|---------------------|
| 结构 | 嵌套对象 | 扁平列 |
| 特征寻址 | `feature_id` 字段 | 列名直接编码 `fid` |
| 序列组织 | 单一 `seq`，混合所有域 | 按 4 域拆分为 45 列 |
| 序列字段 | `item_id`/`action_type`/`timestamp` 内联 | 分散到不同 `domain_x_seq_*` 列 |
| Context Features | 独立语义块 | 合并入 `user_int_feats_*` 或 `item_int_feats_*` |
| 类型信息 | `feature_value_type` 字段显式声明 | 由列名前缀隐式区分 |

## 七、建模挑战关键点

1. **统一 tokenization** — 如何把序列 token 和非序列 token 放入同一序列
2. **同构 block 设计** — 一个 block 同时处理 self-attention（序列）和特征交叉（非序列）
3. **多域序列融合** — Domain A/B/C/D 四个域的序列如何建模关系
4. **延迟约束** — 模型复杂度需控制在推理延迟预算内，不能无限堆叠层数
5. **稠密 + 稀疏统一** — float 向量（Cross Features）与 int ID（User/Item Features）的异构表示对齐
