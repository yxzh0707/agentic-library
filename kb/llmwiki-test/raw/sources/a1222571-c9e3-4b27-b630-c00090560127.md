# HSTU — 赛题 baseline 的核心 block，也是 scaling law 的骨架

> arxiv 2402.17152 | Meta | ICML 2024 | 万亿参数生成式推荐

## 这篇为什么相关

两条原因：
1. **TAAC2026 baseline 直接用 HSTU** — baseline GitHub repo (suyanli220) 就是 HSTU blocks + Rotary positional bias 处理 [CLS, User, Item, Sequence] 四类 token
2. **它是赛题里 Scaling Law 创新奖最自然的 baseline** — HSTU 是第一个在推荐域跑出类 LLM scaling 行为的架构

## 架构最小描述

每层三个 sub-layer：
1. **Pointwise Projection** — token-wise 投影（每个 token 独立处理，无跨 token 交互）
2. **Spatial Aggregation** — 这是真正做 token 间交互的地方，类似 attention 但替换 softmax 为 pointwise normalization
3. **Pointwise Transformation** — token-wise 变换

关键修改：**用 pointwise normalization 替代 softmax**，原因是推荐场景的"词表"高基数、非平稳（每天有新 item 加入），softmax 在高基数 token 间的归一化会被冲掉。

## 速度数字（可以当作工程预算上限）

- 8192 长序列：比 FlashAttention2 Transformer 快 5.3x ~ 15.2x
- M-FALCON 微批方案：相同推理预算下能 serve 285x 更复杂的模型，端到端再加 1.50x ~ 2.48x 加速

这两个数字直接说明：在赛题"延迟超时直接作废"的约束下，HSTU 比标准 Transformer 留出更大的容量预算。

## 我对赛题的 framing

HSTU 不是赛题的最终答案，但它是**最容易合规跑通**的 baseline：
- 序列侧：HSTU block 处理 4 个 domain interleaved 后的事件流
- 非序列侧：作为"特殊 token"塞进同一序列（baseline 就是这么干的，[CLS, User, Item, Sequence]）
- Scaling：HSTU 已被证明可以同时增大 W/D/L 拿到平稳 AUC 提升

但 HSTU 没有显式区分 S/NS 参数（不像 OneTrans 那样 NS 用 token-specific 参数）。**这是改进口子**：把 OneTrans 的"S 共享 + NS 独占"参数规则套到 HSTU 的 spatial aggregation 上，可能就是一个有 paper 价值的 Unified Block 创新。

## 与 baseline (DeepContextNet) 的关系

baseline 用了 HSTU + Muon optimizer (SVD-based 正交化)。HIDDEN_DIM=128, BLOCK_DEPTH=4, lr=2e-4, SESSION_GAP=1800s。这是**起跑线** — 任何提交先要在这个配置上做对照。
