# TAAC2026 / KDD Cup 2026 赛题 framing

## 一句话
用一个**同构主干 + 可堆叠统一 block**，同时吃下两类向来分裂的输入：用户的多域行为序列 token、广告/上下文/交叉等非序列字段 token，输出 pCVR。

## 为什么这是个真问题，而不是 leaderboard 玩具

工业推荐栈里这两类信号几十年是分开建模的：
- 序列侧吃 (item_id, action_type, timestamp)，模型族是 DIN→DIEN→SIM→TWIN→SASRec→BERT4Rec→HSTU→TransAct
- 特征交叉侧吃匿名 int 字典 + dense 向量，模型族是 Wide&Deep→FM/FFM→DCN→xDeepFM→AutoInt→Wukong→HiFormer→HyFormer→OneTrans→InterFormer

双轨并行带来的代价：跨范式交互浅（两路特征只在最顶层 concat）、目标不一致（序列子模 next-item，CTR 子塔 BCE）、不可扩展（加层只能加在某一支）、工程复杂（两套 feature pipeline + 两套 serving）。赛题的本意是逼参赛者在同一 token 流里把两件事一起干。

## 硬约束
- 主指标 ROC-AUC，AUC ≤ 0.50 不上榜
- 推理延迟有上限，超时直接作废 → 不能无脑堆层、不能 KV 长序列裸跑
- 禁止 ensemble → 不能靠投票拉分
- 同分按延迟升序打破平局 → 延迟其实是第二指标
- 两个独立的论文奖：Unified Block 创新 / Scaling Law 创新

## 数据形态需要记住的几个事实
- 每条样本 = (用户, 上下文, 目标广告) 三元组
- HuggingFace 样本 demo_1000.parquet 是扁平 120 列；官方原始是嵌套 JSON
- 序列被拆成 4 个 domain：A(9 列)/B(14 列)/C(12 列)/D(10 列)，每列是 list<int64> 可能含 null
- 非序列特征 70 列：user_int_feats_* (46) / user_dense_feats_* (10) / item_int_feats_* (14)
- Context 在 parquet 里被合并进 user/item int_feats
- Cross Features 是 float_array，是少数 dense 信号；其他全是匿名 int 字典

## 我的 framing 视角
这个赛题表面是 CVR，本质是在问：**把序列 token 和字段 token 投到同一表示空间，让 self-attention/cross 在同一层发生，是否能拿到比双轨更高的 AUC，并且延迟可控？**

所以后续摄入的所有外部资料，应该围绕三个轴归类：
1. **同构 token 化**：怎么把序列事件和非序列字段编码成可被同一 block 消化的 token
2. **统一 block 设计**：单个 block 同时承担 self-attention（序列内）+ feature cross（非序列内）+ cross attention（两类之间）
3. **延迟可控的 scaling**：在不能 ensemble、有延迟预算的前提下，如何往深/宽 scale
