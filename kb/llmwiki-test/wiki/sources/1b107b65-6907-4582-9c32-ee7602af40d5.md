# 延迟工程线 — 赛题的隐藏 boss

本源文档系统性地阐述了在 TAAC2026/KDD Cup 2026 推荐系统赛题中，延迟作为淘汰线与排名规则的核心地位。它提供了从理论到实践的完整延迟优化框架，包括三大延迟杠杆、常见误区以及赛题专属的决策树。

核心论点是：在赛题中，延迟不是普通的优化项，而是直接决定模型是否有效的“淘汰线”。必须优先保证延迟达标，再优化模型效果。文档详细介绍了计算复杂度、请求结构和内核与精度三大杠杆，并强调了“先塞满延迟预算，再优化模型”的工程流程。

# Cross-request KV Cache

Cross-request KV Cache 是一种利用赛题样本结构实现延迟优化的关键技术。在 TAAC2026 赛题中，样本结构为 (用户, 上下文, 目标广告)，一次用户请求需要对多个候选广告进行打分，但用户的序列是同一个。

## 原理与实现

标准做法是每个 (user, candidate) 对独立前向计算，导致序列侧重复计算。Cross-request KV Cache 通过以下方式优化：
- **序列侧计算一次**：将用户序列的 Key 和 Value 缓存起来。
- **候选广告独立计算**：每个 candidate 只计算自己的 NS token 和 cross-attention，复用缓存的 KV。

## 收益与适用场景

根据 OneTrans 论文实测，该技术可带来：
- **运行时降低 30%**
- **内存减少 50%**

这是一种“近免费”的延迟收益，因为它不影响离线 AUC。特别适用于推荐系统中同一用户多候选广告的场景。

## 与现有技术的关联

Cross-request KV Cache 是 [[one-trans]] 模型架构的核心创新之一，也是 [[延迟优化]] 在请求结构杠杆下的具体实践。

# 延迟决策树

延迟决策树是针对 TAAC2026 赛题样本结构的系统化延迟优化决策流程，为工程师提供快速定位优化方向的实用工具。

## 决策流程

样本进来后，按以下路径进行决策：

### 序列侧（4 个 domain，长度 N）
- **同一 user 多 candidate？** 是 → 必须开启 KV cache。
- **长度 N > 1000？** 是 → 使用 HSTU 替代标准 self-attention，或采用 GSU 风检索。

### 非序列侧（70 列字段）
- **多少 token？** 多 → token-specific 参数昂贵 → 考虑 group-wise + 共享子集。
- **dense 特征（10 列 user_dense）**：单独投影 vs 拼进 int 通道 → 影响内存带宽。

## 使用场景

该决策树帮助工程师在赛题约束下，优先处理高收益优化点，确保延迟达标后再优化模型效果。

# HSTU

HSTU 是一种推荐用于替代标准自注意力的模型架构，以降低计算复杂度，是 TAAC2026 赛题中延迟优化的核心选择之一。

## 延迟优化角色

在赛题中，HSTU 通过其 spatial aggregation 机制，实测比 FlashAttention2 快 5.3x ~ 15.2x（在 8192 序列长度上）。这使得在 5ms 单样本推理预算下，HSTU 4 层 128 维模型可在 1-2ms 完成序列侧计算。

## 与标准 Self-Attention 的对比

- **标准 Self-Attention**：计算复杂度 O(N^2 d)，在长序列下延迟高。
- **HSTU**：计算复杂度更低，适合小 N 大 d 场景，可带来 5-15 倍的容量预算提升。

## 工程实践

在赛题延迟决策树中，当序列长度 N > 1000 时，推荐使用 HSTU 替代标准 self-attention。结合 Cross-request KV Cache，可进一步摊薄序列侧计算成本。

# OneTrans

OneTrans 是一种模型架构，其核心创新是 Cross-request KV Cache，通过利用请求结构实现近免费的延迟收益。

## 核心创新：Cross-request KV Cache

OneTrans 在推理时缓存用户序列的 KV，避免重复计算。具体实现为：
- **序列侧算一次**：缓存用户序列的 Key 和 Value。
- **候选广告独立计算**：每个 candidate 只计算自己的 NS token 和 cross-attention。

## 延迟优化收益

根据论文实测，OneTrans 可带来：
- **运行时降低 30%**
- **内存减少 50%**

## 训练与推理统一

OneTrans 强调训练与推理的统一，采用 causal + 两阶段切分，避免因推理优化与训练分开而导致的 attention pattern 破坏。

# Project Overview

本维基项目旨在系统性地记录和分析推荐系统领域的最新发展，特别是围绕深度学习模型架构和工业应用挑战。当前维基覆盖了从基础概念到具体赛题分析的多个层面。

本维基的核心主题之一是**推荐系统模型架构**，特别是如何通过创新的架构设计来解决工业界的实际问题。近期，维基引入了对 **TAAC2026/KDD Cup 2026 推荐系统赛题**的深入分析，该赛题的核心挑战是设计一个**统一主干架构**，以打破工业推荐中常见的双轨建模瓶颈。这一分析涵盖了赛题背景、核心要求、模型架构对比（如 OneTrans、HSTU、MTGR）、创新方向（如异构 Transformer、Sample-level Token）以及工程约束（如延迟优化和 Scaling Law 实验）。

此外，维基还记录了关于序列与非序列特征同构处理、双轨建模瓶颈等关键概念的定义和讨论。随着新赛题和新技术的不断涌现，维基持续更新以反映该领域的最新进展。

最新引入的**延迟工程线**分析强调了延迟在赛题中的核心地位，将其视为淘汰线与排名规则。该分析提供了三大延迟杠杆（计算复杂度、请求结构、内核与精度）、常见误区以及赛题专属的延迟决策树，为推荐系统模型的实时部署提供了系统性指导。维基现在涵盖了从模型架构设计到工程优化的完整知识链。
