# 综合作战计划 v2（吸收第二轮深度搜索后的修订）

此源文件是针对 TAAC2026/KDD Cup 2026 推荐系统赛题的综合作战计划 v2 版本，整合了第二轮深度搜索后的技术要点。计划提出了一个分阶段的实验路线，从基础 baseline 跑通到冲击论文奖项，并详细阐述了 Token 化层设计、训练目标、工程预算及论文奖项策略。

## 三档实验路线

### Tier 1 — 必做（最小可行，1-2 周）
目标：在赛题数据上跑通一个能交的 baseline，建立提交流水线。
- 跑 baseline (DeepContextNet) 并记录 AUC 与单样本延迟。
- 加 **Group-Layer Normalization** (MTGR)：几乎零代价 +0.1~0.3% AUC。
- 加 **多任务 head** (ESMM 风)：CTR head + CVR head 共享 backbone，+0.3~1.0% AUC。
- 加 **Next Action Loss** 辅助 (TransAct V2)：+0.1~0.3% AUC。
- NS 侧 token 数从 baseline 的 2 个扩到 group-wise 8-16 个 (OneTrans Group-wise tokenizer)：+0.3% AUC。

### Tier 2 — 拼 leaderboard（2-4 周）
目标：把单模型推到 leaderboard 前列。
- 把 backbone 从 baseline HSTU 换成 **MTGR-style HSTU + GLN + dynamic mask**。
- NS token 用 **OneTrans 的 token-specific 参数**（S 共享 + NS 独占）。
- 训练阶段开 **大 OneTrans-L teacher，蒸馏到 MTGR-S student**。
- **timestamp-aware RoPE**（替换 baseline 的对数时间分桶 + 标准 Rotary）。
- 引入 **cross-request KV cache**（OneTrans）— 纯延迟收益，破排名平局必备。
- **Muon optimizer** for backbone, AdamW for embedding（混合）— 训练 2x 效率。

### Tier 3 — 论文奖（持续投入）
目标：拿 Unified Block Innovation Award 或 Scaling Law Innovation Award。
- **路径 A — Unified Block 创新**：在 MTGR 上把 OneTrans 的参数分化 + HyFormer 的 Query Decoding 作为层间池化算子组合，提出新 block。具体做法：偶数层标准 unified self-attention，奇数层 Query Decoding 风 cross-attention，引入 **field-aware attention** (FAT) 在 NS 内部。
- **路径 B — Scaling Law 创新**：在赛题数据上证明 NS token 数量 T 是独立的 scaling 维度。具体做法：跑五档模型（W: 64/128/256/512/1024）× 三档 NS token 数（4/16/64），画 (FLOPs, AUC) 双对数曲线，跟 HSTU、OneTrans、Wukong 的 published curve 对比，引入 **MFU 度量**（Kunlun）作为效率维度。

## Token 化层设计
综合 OneTrans 与 Sample Is Feature 的折中方案：
- 序列侧：4 域 timestamp-aware interleave，每事件 = item_id_emb + action_type_emb + time_bucket_emb + domain_type_emb（拼接而非加法）。
- 非序列侧：group-wise，每个 group 一个 NS token，token-specific 参数。
- 最终预测：用 candidate token 的 hidden 通过一个 head 输出 pCVR，不用 CLS。

## 训练目标
```
loss = 0.7 * BCE(pCVR_pred, y_cvr)
     + 0.2 * BCE(pCTR_pred, y_ctr)            # ESMM-style multi-task
     + 0.05 * NextActionLoss(seq)              # TransAct V2 自监督
     + 0.05 * KL(student, teacher)             # 蒸馏（Tier 2+）
```

## 工程预算估算
- Tier 1 单模型训练：1 ~ 4 GPU 天
- Tier 2 加蒸馏：3 ~ 10 GPU 天（teacher + student）
- Tier 3 scaling 曲线：每档模型独立训，总 30 ~ 60 GPU 天

## 必读优先级
1. OneTrans (2510.26104) — 赛题官方推荐
2. HSTU (2402.17152) — baseline backbone
3. MTGR (2505.18654) — 工程版
4. Kunlun (2602.10016) — MFU 优化（Tier 2 的延迟来源）
5. MixFormer (2602.14110) — 直接对手
6. HyFormer (2601.12681) — 层间交错思路
7. FAT / Structured Expressivity (2511.12081) — 理论框架，论文 Section 5 必引
8. Sample Is Feature (2604.15650) — Tier 3 路径 B 的对手
9. Wukong (2403.02545) — Scaling law 起点
10. TransAct V2 (2506.02267) — Next Action Loss

## 不确定项（开工后立刻验证）
1. 序列实际长度分布（决定要不要 GSU 风检索）
2. 延迟预算具体数值（决定模型大小上限）
3. label_type 字段编码的语义（决定 ESMM 怎么套）
4. 4 个 domain 的事件数比例（决定 type embedding 维度）
5. user_dense_feats（10 列 cross feature）数值范围（决定 normalize 策略）

## 论文奖项的两条 framing
- **Unified Block 奖**：组合贡献 — MTGR 的 GLN + OneTrans 的参数分化 + HyFormer 的层间交错 + FAT 的 field-aware attention，作为一个新 block。
- **Scaling Law 奖**：在赛题数据上画三维 scaling 曲线（W × D × T），用 FAT 的 Rademacher 框架解释为什么斜率正，用 Kunlun 的 MFU 框架解释为什么效率高。

两个方向都不要追求"全新"，而是"在赛题 setting 上首次验证 + 解释"。
